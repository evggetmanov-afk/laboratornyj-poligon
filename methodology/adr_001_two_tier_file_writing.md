# ADR 001: Двухуровневая модель записи и генерации файлов

## 1. Контекст и проблематика
Изначально вся запись файлов в системе производилась через терминальные Heredoc-команды (`cat << 'EOF'`). При масштабировании выгрузки кода и текстовых заметок в каталоги `projects/` проявились ограничения:
1. Зависания терминала из-за скрытых управляющих символов и нарушений форматирования маркерных строк.
2. Риск сбоя бутстраппинга: попытка полностью отказаться от Heredoc и перейти на генератор скриптов (`apply_payload.py`) заблокировала возможность развертывания самого скрипта в чистой среде, где этот инструмент еще физически отсутствует на диске.

## 2. Принятое решение
Принять **Двухуровневую модель работы с файлами (Two-Tier File Writing Architecture)** с четким разделением по контурам и режимам:

### Уровень 1: Ядро и аварийный режим (Heredoc Invariant)
- **Область применения:** Системные файлы ядра (`PROJECT_PASSPORT.md`, `methodology/`, `specs/`, `scripts/`).
- **Механизм:** Терминальный монолитный `cat << 'EOF'` строго по стандарту `specs/terminal_heredoc_standard.md`.
- **Назначение:** Бутстраппинг среды, модификация правил и восстановление работоспособности системы при сбоях.

### Уровень 2: Проекты и штатный режим (Payload Generator)
- **Область применения:** Рабочие каталоги проектов (`projects/`).
- **Механизм:** Пакетный скрипт `scripts/apply_payload.py` по спецификации `specs/payload_generator_spec.md`.
- **Назначение:** Высокоскоростная пакетная выгрузка мультифайловых структур, кода и заметок без риска зависания терминала и без ограничений по специальным символам.

## 3. Системные инварианты
1. **Bootstrap-автономия ядра:** Ядро никогда не зависит от внешних парсеров для собственной модификации.
2. **Pre-flight check для Heredoc:** Модель обязана иметь в активном контексте окна текст `specs/terminal_heredoc_standard.md` перед генерацией Heredoc-команд для Уровня 1.
3. **Строгая граница ответственности:** Скрипту `scripts/apply_payload.py` запрещено модифицировать системные файлы ядра вне прямого указания в контракте.

## 4. Последствия
- **Положительные:** 
  - Устранен риск взаимной блокировки (deadlock) при инициализации и восстановлении системы.
  - Обеспечена надежная пакетная генерация любого количества файлов в проектах за один такт.
- **Отрицательные / Накладные расходы:**
  - Необходимость поддерживать две спецификации стандартов (`specs/terminal_heredoc_standard.md` и `specs/payload_generator_spec.md`).
