# Инженерный бриф: Автоматическое извлечение кода из веб-чата в локальные файлы через Playwright (CDP)

---

### 1. Суть и назначение архитектуры

Технология заменяет ручной цикл **«выделить текст $\rightarrow$ `Cmd+C` $\rightarrow$ запустить скрипт `pbpaste`»** прямым программным мостом между браузером и файловой системой macOS.

* **Было:** человек выступает промежуточным буфером данных (копирует ответ, следит, чтобы в буфер не попало лишнее, запускает сохранение).
* **Стало:** локальный скрипт подключается к уже открытому окну браузера через **Chrome DevTools Protocol (CDP)**, считывает последний ответ модели из дерева элементов (DOM), извлекает маркер пути файла и атомарно записывает код на диск.

---

### 2. Схема движения данных

```
+------------------------------------------------------------------------+
|                     GOOGLE CHROME (порт 9222)                          |
|  [Открыта вкладка с веб-чатом Исполнителя (Gemini / Claude / ChatGPT)]  |
|                                                                        |
|  Ответ модели:                                                         |
|  ### FILE: src/auth/jwt_handler.py                                     |
|  def create_token(...):                                                |
|      ...                                                               |
+------------------------------------------------------------------------+
                                    |
                        (Чтение DOM через CDP)
                                    v
+------------------------------------------------------------------------+
|                      RAYCAST / PYTHON-СКРИПТ                           |
|                                                                        |
|  1. playwright.connect_over_cdp("http://localhost:9222")               |
|  2. locator("...").nth(-1).inner_text()                                |
|  3. re.match(r'### FILE:\s*([^\s]+)')  --> path = src/auth/jwt_handler.py|
|  4. write_text(path, code)                                             |
|  5. macOS notify + afplay (звуковое подтверждение)                     |
+------------------------------------------------------------------------+
                                    |
                                    v
+------------------------------------------------------------------------+
|                   ЛОКАЛЬНЫЙ ДИСК (VAULT_DIR)                           |
|  Файл src/auth/jwt_handler.py обновлен за 0.2 секунды                  |
+------------------------------------------------------------------------+

```

### 3. Необходимый стек и подготовка окружения

1. **Библиотека автоматизации:**
```bash
pip3 install playwright

```


2. **Браузер с портом отладки:**
Chrome должен быть запущен с флагом `--remote-debugging-port=9222`. Это открывает локальный интерфейс для чтения открытых вкладок.
3. **Окружение исполнения:**
Любой менеджер горячих клавиш (Raycast, Alfred, системные Shortcuts) или фоновый watcher.

---

### 4. Ключевые компоненты решения

#### А. Запуск браузера (ярлык / команда)

Чтобы не вводить команду в консоль каждый раз, создается терминальный алиас или однострочный скрипт Automator:

```bash
/Applications/Google\ Chrome.app/Contents/MacOS/Google\ Chrome --remote-debugging-port=9222 --user-data-dir="$HOME/Library/Application Support/Google/Chrome-Dev"

```

*(Параметр `--user-data-dir` позволяет держать отдельный профиль с постоянной авторизацией в веб-чатах).*

#### Б. Слой захвата данных (Playwright CDP)

```python
from playwright.sync_api import sync_playwright

def get_latest_chat_response(port: int = 9222) -> str:
    with sync_playwright() as p:
        browser = p.chromium.connect_over_cdp(f"http://localhost:{port}")
        # Получаем первую активную страницу
        page = browser.contexts[0].pages[0]
        
        # Селектор последнего сообщения ассистента в DOM
        # (универсальный поиск по markdown-контейнерам)
        messages = page.locator("message-content, .model-response-text, [data-message-author-role='assistant']")
        if messages.count() == 0:
            raise RuntimeError("Сообщений модели не обнаружено")
        
        return messages.nth(-1).inner_text()

```

#### В. Слой синтаксического разбора и сохранения на диск

Сохраняется ваш отлаженный парсер:

* Поиск тега `### FILE: <относительный/абсолютный_путь>` в первых 5 строках.
* Срезка служебных маркеров окончания блока (`<<<FILE_CONTENT_END>>>`).
* Запись содержимого через `pathlib.Path.write_text(..., encoding="utf-8")`.
* Системное уведомление macOS (`display notification`) и звуковой отклик (`afplay`).

---

### 5. Эксплуатационные преимущества и риски

| Параметр | Обычный буфер (`pbpaste`) | Playwright через CDP |
| --- | --- | --- |
| **Трудоемкость** | 3 действия: выделить, нажать `Cmd+C`, вызвать Raycast | 1 действие: нажать шорткат в Raycast (или 0 действий по таймеру) |
| **Риск ошибки буфера** | Высокий (случайно скопировали другой текст, зацепили UI) | Нулевой (скрипт парсит строго блок сообщения в DOM) |
| **Зависимость от верстки** | Отсутствует | Умеренная (селектор контейнера сообщения может поменяться при апдейте сайта) |
| **Затраты на API** | $0 | $0 (работа идет в обычном веб-интерфейсе) |

### 6. Дорожная карта внедрения (Next Steps)

1. **Этап 1:** Запуск Chrome с отладочным флагом и проверка доступности порта `http://localhost:9222` в браузере.
2. **Этап 2:** Замена функции `get_clipboard()` на `get_text_from_browser()` в вашем скрипте Raycast.
3. **Этап 3:** Добавление проверки флага завершения стриминга (чтобы скрипт не читал полупустое сообщение, пока нейросеть еще печатает).
4. **Этап 4 (Полный цикл):** Добавление обратного действия — скрипт сам нажимает на поле ввода чата, отправляет туда файл с ТЗ от Архитектора и жмет кнопку отправки.
