Инженерное решение по передаче контекста между сессиями (чатами) строится на отделении **вычислительной среды** (LLM-сессия) от **состояния системы** (файловое хранилище / Git).

Чат с LLM рассматривается как эфемерный воркер без сохранения состояния (stateless worker). Вся непрерывность обеспечивается через локальные файлы на диске.

---

### Архитектурная модель: «Внешнее состояние + Тактовый снимок»

Вместо ручного копирования текстов формируется конвейер из трех компонентов:

1. **SSOT (Single Source of Truth):** Локальная папка проекта на диске (структура Markdown и JSON под Git).
2. **Handoff-контейнер (`STATE.md`):** Единственный стандартизированный файл среза, фиксирующий текущее состояние, инварианты и следующий шаг.
3. **Механический транспорт:** Локальный скрипт автоматизации (Python/Shell), который собирает контекст перед стартом нового чата и раскладывает результат после завершения сессии.

```text
[Текущий чат LLM]
       │
       ▼ (выгрузка кванта передачи)
[STATE.md] ◄─── git commit ─── [Локальный Vault / Git]
       │
       ▼ (сборка промпта скриптом / шорткатом)
[Новый чат LLM]

```

### 1. Спецификация файла передачи (`STATE.md`)

Файл `STATE.md` живет в корне рабочей директории задачи и перезаписывается в конце каждой результативной сессии.

```markdown
---
task_id: "TENNIS-ANALYTICS-PIPELINE"
revision: 14
timestamp: "2026-10-24T13:30:00"
status: "IN_PROGRESS"
---

# SYSTEM HANDOFF CONTRACT

## 1. INVARIANTS & CONSTRAINTS (НЕОБСУЖДАЕМЫЙ БАЗИС)
- [DECISION_LOG]: Ведение ADR обязательно (ошибочность отказа от журнала зафиксирована).
- [ONTOLOGY]: Использовать только закрытый словарь действий: `serve_execution`, `rally_drive`, `attack_down_the_line`, `defensive_slice`, `volley_execution`.
- [DATA_SCHEMA]: Валидация строго по JSON Schema Draft-07 (`TennisRallyFragment`).
- [FORBIDDEN]: Запрещены субъективные/оценочные категории и рассуждения общего характера.

## 2. RECENT DECISIONS (ADR DELTA)
- ADR-006: Отказ от ручного ведения логов признан ошибкой. Возвращен формат легковесных ADR-карточек в Obsidian.
- ADR-007: Зонирование корта зафиксировано через двусоставные ключи `[глубина]_[ширина]`.

## 3. ARTIFACT STATE
- Файлы в фокусе:
  * `schemas/rally_fragment.schema.json` (заморожен)
  * `ontology/court_grid.md` (заморожен)
  * `src/aggregator.py` (требуется реализация)

## 4. IMMEDIATE ACTION (ТАКТОВЫЙ ШАГ)
- Объект: Разработка архитектуры `aggregator.py`.
- Действие: Построение графа переходов состояний (State Transition Matrix) на основе входного потока JSON-карточек розыгрышей.
- Ожидаемый вывод: Код модуля агрегации на Python 3 без сторонних зависимостей.

```

### 2. Механический транспорт (Автоматизация сборки и разборки)

Чтобы исключить рутинные операции с буфером обмена, процесс автоматизируется минимальным локальным скриптом `handoff.py`.

#### Скрипт подготовки контекста для нового чата:

```python
#!/usr/bin/env python3
"""
Сборщик входного промпта для нового чата.
Читает STATE.md, подтягивает связанные схемы и выводит готовый payload в stdout/буфер.
"""
import sys
from pathlib import Path

BASE_DIR = Path(__file__).resolve().parent

def build_context():
    state_file = BASE_DIR / "STATE.md"
    schema_file = BASE_DIR / "schemas" / "rally_fragment.schema.json"

    if not state_file.exists():
        print(f"Error: {state_file} not found", file=sys.stderr)
        sys.exit(1)

    state_content = state_file.read_text(encoding="utf-8")
    schema_content = schema_file.read_text(encoding="utf-8") if schema_file.exists() else "{}"

    payload = f"""<system_state>
<instruction>
Ты инженерный модуль исполнения. Действуй строго в рамках ограничений, зафиксированных в STATE.md.
Любые предложения вне текущей задачи и инвариантов отклоняются.
</instruction>

<state_contract>
{state_content}
</state_contract>

<reference_schema>
{schema_content}
</reference_schema>
</system_state>
"""
    return payload

if __name__ == "__main__":
    print(build_context())

```

### 3. Регламент протокола передачи (Порядок действий)

```markdown
1. Завершение сессии N:
   - В текущем чате выполняется команда:
     «Сформируй блок STATE.md для текущего момента: инварианты, принятые решения, актуальный код и задачу на следующий такт».
   - Содержимое сохраняется в локальный `STATE.md`.
   - Выполняется фиксация в репозитории: `git commit -am "chore: handoff state rev X"`.

2. Старт сессии N+1:
   - Запуск генератора промпта (в терминале или по кнопке контроллера):
     `python3 handoff.py | pbcopy`
   - Вставка собранного контекста в первый запрос нового чата.
   - Модель начинает работу сразу с тактового шага, имея жесткие рамки инвариантов и актуальную схему.

```

### 4. Защита от сбоев (Fail-Safe механизмы)

* **Защита от семантического дрейфа:** Если модель в новом чате начинает переопределять термины или давать советы общего плана, первая фраза оператора: `«Соблюдай инварианты из блока 1 в STATE.md»`.
* **Изоляция веток:** Если в ходе сессии возникла гипотеза, требующая пересмотра онтологии или структуры JSON, она не вносится в основной `STATE.md`, а оформляется отдельным драфтом решения (ADR-draft).
* **Принцип параллельных контуров:** При смене логики обработки старый работающий код или схема не модифицируются «на лету» в чате — создается параллельная спецификация `v2`, чтобы не сломать валидацию уже размеченных карточек.
