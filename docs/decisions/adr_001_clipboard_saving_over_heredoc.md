# Архитектурное решение: Замена Heredoc на чтение системного буфера обмена (save_clip.py / save)

## 1. СЛОЙ A (Голос и проблема)
- **Проблема:** Постоянные сбои при записи файлов через Heredoc (`cat << 'EOF'`) в среде macOS Zsh (`unknown file attribute:`, ложный запуск строк текста как команд `command not found:`, падения из-за кавычек и спецсимволов).
- **Коллизия «курицы и яйца»:** Попытка использовать `apply_payload.py` для обновления скриптов ядра создавала тупик в случае поломки самого интерпретатора скрипта.

## 2. СЛОЙ B (Физика среды)
- **Терминал macOS и Zsh:** Вставка многострочного текста (`Cmd+V`) в интерактивную строку парсится шеллом построчно. Скобки воспринимаются как глоб-квалификаторы, а переводы строк — как отправка команд на исполнение.
- **Системный буфер (`pbpaste`):** Нативная утилита macOS читает поток байт напрямую из памяти операционной системы (`NSPasteboard`), минуя интерактивный парсер командной строки Zsh.

## 3. СЛОЙ C (Инвариант решения и правила)
- **Инструмент:** Создана утилита `scripts/save_clip.py`, считывающая буфер через `pbpaste`, извлекающая целевой путь из первой строки `### FILE: <path>` и атомарно записывающая файл на диск с автосозданием каталогов.
- **Интерфейс:** В конфигурацию оболочки (`~/.zshrc`) внедрен системный алиас `save`.
- **Регламент записи:**
  1. Модель выдает файл с маркером `### FILE: <path>` в первой строке.
  2. Оператор копирует блок кнопкой интерфейса.
  3. В терминале выполняется команда `save`.
- **Negative Constraints:**
  - Категорически запрещено использовать `cat << 'EOF'` (Heredoc) для записи файлов.
  - Запрещена ручная вставка (`Cmd+V`) содержимого файлов в командную строку терминала.
