# ADR-006: Мгновенная Read-Only диагностика без лишних согласований

## 1. Проблема (A)
Требование запрашивать подтверждение на абсолютно каждую команду терминала парализовало работу: на банальный осмотр каталога (`ls`) или проверку статуса Git (`git status`) тратился отдельный холостой такт диалога туда-обратно.

## 2. Физика среды и барьер (B)
Read-only команды (`ls`, `cat`, `git status`, `git diff`, `pwd`) физически не изменяют состояние файловой системы SSD, не двигают указатели коммитов и не несут риска разрушения среды. Задержка в их выполнении вызвана исключительно избыточной бюрократизацией регламента.

## 3. Решение (C)
- Введена двухуровневая модель защитного барьера (пункт №9 Паспорта).
- Немодифицирующие команды осмотра среды разрешено генерировать немедленно в ответе модели без предварительного запроса санкции.
- Барьер подтверждения сохранен строго для операций модификации (Write/Exec, правка файлов, коммиты, запуск скриптов).

## 4. Ограничения (Negative Constraints)
- Запрещено маскировать модифицирующие команды под read-only (например, использование `cat` с перенаправлением `>` или запуск скриптов с побочными эффектами).
- Запрещено требовать подтверждения на базовые однострочные команды осмотра.
