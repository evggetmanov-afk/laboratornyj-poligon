# ADR-005: Обязательный Pre-Flight Check терминального стандарта Heredoc

## 1. Проблема (A)
Модель генерировала команды `cat << 'EOF'` с пробелами перед маркером `EOF`, разрывала блоки разметкой или вставляла незаэкранированные символы. Терминал зависал в ожидании закрытия потока ввода, блокируя сессию.

## 2. Физика среды и барьер (B)
В zsh/bash синтаксис Heredoc крайне чувствителен к маркерам: даже один невидимый пробел перед `EOF` превращает маркер в обычную строку данных, и терминал «глотает» весь последующий ввод в бесконечный буфер. Модель склонна забывать эти детали при длительном диалоге, если стандарт отсутствует в активном окне внимания.

## 3. Решение (C)
- В пункт №9 Паспорта внедрен Pre-flight check: если файл `specs/terminal_heredoc_standard.md` отсутствует в контексте текущего чата, генерация команд записи категорически запрещена.
- Модель обязана сначала потребовать чтение стандарта через `cat specs/terminal_heredoc_standard.md`.

## 4. Ограничения (Negative Constraints)
- Запрещено выдавать код на изменение файлов ядра до подтверждения наличия стандарта в окне диалога.
- Запрещено разбивать Heredoc пояснительным текстом на несколько сообщений.
