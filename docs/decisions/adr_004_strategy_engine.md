# ADR-004: Двухконтурный генератор и детерминированный исполнитель стратегий

- **Статус:** Утверждено (Approved)
- **Дата:** 25 октября 2026 г.
- **Область:** projects/strategy_engine, .swap/TASK.md, scripts/

## A. Проблема (Context & Dilemma)
Поручение языковой модели одновременно синтезировать стратегию и напрямую манипулировать окружением в режиме диалога порождает энтропию:
1. Семантический дрейф и «ленивый» код при многократных итерациях.
2. Недетерминированность выполнения команд и пропуск шагов валидации.
3. Высокая когнитивная нагрузка на оператора при ручном копировании промежуточных путей и параметров.

## B. Физика среды (Environmental Constraints)
1. macOS / APFS / Python 3 CLI обеспечивают строго детерминированный запуск через `subprocess.run` с фиксацией кодов возврата (0 / non-zero).
2. Формат файлов Markdown с префиксом `CMD:` устойчив к разрывам синтаксиса системного буфера обмена macOS (`pbpaste`).
3. Изоляция проектов в `projects/strategy_engine/` гарантирует неизменность ядра (`specs/`, `scripts/`).

## C. Решение и регламент (Decision & Negative Constraints)
1. **Разделение контуров:**
   - **Контур А (Генератор / `planner.py`):** Формирует карточку `STRAT-YYYYMMDD-XX.md` с явными Negative Constraints и нумерованными шагами.
   - **Контур С (Раннер / `runner.py`):** Запускает команды `CMD:`, проверяет префлайт-условия, прерывает исполнение при первом ненулевом коде возврата.
2. **Negative Constraints (Запреты):**
   - Запрещено выполнять шаги стратегии при падении хотя бы одной команды.
   - Запрещено затирать существующие файлы стратегий (строгая автонумерация).
   - Запрещено использовать интерактивный ввод в командах раннера.
