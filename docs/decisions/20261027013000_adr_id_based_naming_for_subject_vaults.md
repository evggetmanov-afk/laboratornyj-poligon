# ADR: Использование цифровых идентификаторов (ID-Based Naming) для предметных заметок

## 1. СТАТУС
Принято (Accepted)

## 2. КОНТЕКСТ И ПРОБЛЕМА (Слой A: Телеология)
В предметных хранилищах (аналитика женского тенниса, биомеханика, матчевые инциденты) использование длинных семантических имен создало два критических барьера:
1. **Когнитивный барьер:** Англоязычные технические термины требуют постоянного перевода и загромождают восприятие оператора.
2. **Технический барьер:** Имена на кириллице с пробелами и спецсимволами нестабильны в среде CLI macOS, усложняют работу скриптов (`save_clip.py`, `vahta.py`) и вызывают сбои нормализации Unicode (NFD/NFC).
3. **Хрупкость связей:** Переименование файлов при уточнении теннисной концепции ломает внешние ссылки и историю Git.

## 3. ФИЗИКА СРЕДЫ (Слой B: Ограничения и архитектура)
1. **Среда исполнения (CLI / Git / Python):** Требует неизменяемых детерминированных путей без пробелов, спецсимволов и кириллицы. Идеальный формат — монотонно растущий цифровой идентификатор.
2. **Слой LLM-агентов:** Агенты идентифицируют файлы по системному пути (адресу), а смысл считывают из содержимого: метаданных и заголовка первого уровня (`#`).
3. **Слой интерфейса оператора (Obsidian / Markdown):** Человеческое восприятие требует прямого русского языка. Для устранения "слепоты номеров" в визуальном слое используется плагин отображения заголовков первого уровня (Frontmatter Title / Inline Title), а в терминале — скрипт-индексатор.

## 4. АРХИТЕКТУРНОЕ РЕШЕНИЕ (Слой C: Преобразователь и регламент)

1. **Двухуровневый стандарт именования предметных заметок:**
   - **Физическое имя на диске:** Строго цифровой код без буквенных вставок. Канонический формат — дата с порядковым суффиксом `YYYYMMDD_NN.md` (например, `20261027_01.md`) либо таймстемп `YYYYMMDDHHMMSS.md`.
   - **Смысловой заголовок документа:** Первая строка файла обязана быть заголовком первого уровня на русском языке:
     ```markdown
     # Срыв подачи под давлением во втором сете
     ```

2. **Правила для системных документов полигона (ADR, спецификации):**
   - Системные документы сохраняют префикс монолитного таймстемпа с кратким функциональным суффиксом на латинице: `YYYYMMDDHHMMSS_adr_<краткая_суть>.md`.

3. **Связывание заметок (Вики-ссылки):**
   - В тексте ссылки оформляются строго с отображаемым русским алиасом: `[[20261027_01|Срыв подачи под давлением]]`.

4. **Компенсация терминальной слепоты (CLI-индекс):**
   - Для быстрой идентификации цифровых файлов в терминале без запуска GUI используется легковесный скрипт `scripts/scan_vault.py` (или чтение файла индекса), сопоставляющий имя файла и его заголовок `#`.

## 5. ПОСЛЕДСТВИЯ И ГАРАНТИИ
- **Плюсы:**
  - Полное исключение английского языка из смысловой работы оператора.
  - 100% стабильность путей в bash, Git и Python.
  - Свобода редактирования формулировок заголовков без изменения ссылок и путей в файловой системе.
- **Компенсация рисков:**
  - На случай работы вне Obsidian оператор ориентируется по автогенерируемому локальному индексу с русскими заголовками.
