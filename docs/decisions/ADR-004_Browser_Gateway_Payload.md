# ADR-004: Браузерный шлюз, протокол CONTAINER и транзакционный распаковщик container_gateway.py

## СТАТУС
Принято (ACCEPTED)

---

## A. ПРОБЛЕМА (Контекст и конфликт контрактов)
1. Разрыв состояний (Partial Write): перенос группы взаимосвязанных файлов (скрипт, тесты, манифест, документация) через поштучное копирование и последовательные вызовы `save` перегружает оператора и при любой ошибке оставляет систему в поломанном промежуточном состоянии.
2. Конфликт форматов: существующий скрипт `scripts/apply_payload.py` рассчитан исключительно на чтение локального файла `.swap/TASK.md` и разбор устаревших маркеров `<<<FILE_PATH: ...>>>`. Он не умеет принимать поток данных из стандартного ввода `sys.stdin` через системный буфер macOS (`pbpaste`).
3. Отсутствие транзакционности пакета в легаси-скрипте: `scripts/apply_payload.py` записывает файлы последовательно прямо в цикле[cite: 1]. Если последующий файл заблокирован проверкой безопасности, предыдущие файлы уже физически сохранены на диске[cite: 1].
4. Риск регрессии при модификации ядра: изменение существующего скрипта `scripts/apply_payload.py` на лету создает угрозу поломки действующих сценариев сдачи смены вахты[cite: 1].
5. Уязвимость путей: простая строковая проверка на отсутствие `../` уязвима перед symlink-атаками, скрытыми системными каталогами и записью вне целевого дерева репозитория.
6. Двусмысленность парсинга: обработка произвольного JSON без строгой сигнатуры формата ведет к риску случайного применения сторонних данных из системного буфера обмена.

---

## B. ФИЗИКА СРЕДЫ (Технические ограничения)
1. Шина буфера обмена macOS: конвейер `pbpaste | python3 ...` является основной детерминированной текстовой шиной доставки артефактов из браузера в консоль оператора[cite: 1].
2. Изоляция гипотез (Пункт 8 Паспорта): новый механизм реализуется в виде отдельного инструмента `scripts/container_gateway.py`, сохраняя легаси-скрипт `scripts/apply_payload.py` неизменным до завершения сравнительных испытаний[cite: 1].
3. Трехфазная транзакционность (Validation -> Staging -> Commit):
   - Фаза 1 (Валидация): поиск внешних маркеров, проверка схемы `poly-container/v1`, резолв путей через `os.path.realpath`, проверка контуров доступа[cite: 1]. Любая ошибка отменяет операцию до касания диска[cite: 1].
   - Фаза 2 (Staging): все файлы пакета разворачиваются во временный изолированный каталог транзакции `.swap/tx_<timestamp>/`. Ошибка записи на этом этапе полностью удаляет каталог транзакции, не затрагивая боевое дерево полигона.
   - Фаза 3 (Commit): атомарный перенос проверенных файлов из каталога транзакции в целевые пути через `os.replace`.
4. Модель защищенных контуров:
   - Безусловный запрет: скрытые системные каталоги (`.git/`, `.swap/`), корневые конфигурационные файлы (`.zshrc`, `.env`, `PROJECT_PASSPORT.md`).
   - Контур ядра (требует явного флага `--allow-core`): каталоги `specs/`, `scripts/`[cite: 1].
   - Свободный рабочий контур: `projects/`, `docs/`, `_draft/`, `inbox/`, `ready/`.

## C. РЕШЕНИЕ И ИНВАРИАНТЫ

### 1. Шлюзовой контроллер ветвления (Pre-flight Gate)
- При подготовке одного файла ($N=1$) модель выдает его поштучно через стандартный блок сохранения `save`[cite: 1].
- При подготовке двух и более файлов ($N \geq 2$) модели категорически запрещено выдавать их автоматически[cite: 1]. Модель обязана остановиться, вывести список путей и запросить выбор оператора:
  *«Подготовлено N файлов. Выгрузить пакетом или по одному через save?»*
- Формирование пакета выполняется строго по фразам оператора: **«выгружай пакетом»** или **«контейнер»**.
- Поштучная выдача выполняется строго по ответу: **«по одному»**.

### 2. Фиксированная JSON-схема манифеста
Пакет передается внутри строгих маркеров:
- Маркер начала: `=== START_CONTAINER ===`
- Маркер окончания: `=== END_CONTAINER ===`

Схема манифеста:
```json
{
  "schema": "poly-container/v1",
  "task": "Название кванта задачи",
  "files": [
    {
      "path": "относительный/путь/к/файлу.py",
      "content": "содержимое файла",
      "executable": false
    }
  ]
}
