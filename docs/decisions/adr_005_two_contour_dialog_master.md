# ADR-005: Двухконтурный диалоговый мастер (Контур 1 / Контур 2, Tampermonkey, Elgato Stream Deck)

## A. Проблема (Контекст и симптомы)
1. Смешивание легкого кода, правил и тяжелых бинарных данных/сырья в одной среде перегружает SSD, засоряет Git и замедляет индексацию.
2. Ручная передача артефактов из веб-интерфейса LLM в локальную среду через стандартную вставку (`Cmd+V`, Heredoc) приводит к повреждению экранирования, потере символов новой строки и сбоям протоколов выгрузки.
3. Разрыв между браузером (веб-чат), буфером обмена и терминалом создает операционную рутину и провоцирует человеческие ошибки при запуске утилит конвейера.

## B. Физика среды (Причины и ограничения)
1. **Файловая система SSD и Git:** Git эффективен только для текстовых диффов; тяжелые бинарники в локальном дереве раздувают `.git` без возможности легкого отката.
2. **Облачная синхронизация Google Диска:** Асинхронные блокировки дескрипторов файлов вызывают конфликты при одновременных операциях сборки или коммитах ядра.
3. **Ограничения буфера и эмуляции терминала:** Вставка многострочных блоков через буфер в окно эмулятора терминала с активным zsh/autosuggestions ломает длинные строки и спецсимволы. Безопасна только программная обработка содержимого системного буфера (`pbpaste` / `save_clip.py`).
4. **Аппаратные триггеры:** Клавиатурные сокращения требуют переключения фокуса окон и удержания в памяти десятков хоткеев, что повышает когнитивную нагрузку оператора.

## C. Решение и запреты (Архитектура)
Фиксация двух изолированных контуров («ИЛИ / ИЛИ») с аппаратным и браузерным сопряжением:

### 1. Контур 1: Рабочее ядро (SSD макбука)
- **Назначение:** Постоянный верстак для кода, системных спецификаций, правил и чистых заметок под строгим контролем Git.
- **Инвариант:** Никаких тяжелых бинарников, видео и сырых архивов.

### 2. Контур 2: Операционный цикл (Google Диск)
- **Назначение:** Площадка приема сырья, тяжелых файлов, видео и архивов вне локального Git-репозитория (`Knowledge_Pipeline/`).
- **Связь контуров:** Обмен данными выполняется строго через буферные шлюзы (`inbox/`, `ready/`).

### 3. Инфраструктурный слой связи (Браузер <-> Буфер <-> Аппаратный пульт)
- **Tampermonkey (Браузерный агент):** Пользовательский скрипт в интерфейсе Gemini для чистой выгрузки сгенерированных блоков артефактов (`### FILE: <путь>`) в системный буфер обмена macOS в один клик без паразитных метаданных интерфейса.
- **scripts/save_clip.py (Системный алиас `save`):** Автономный парсер буфера на стороне macOS, выполняющий атомарную запись в целевой файл ядра без открытия терминального редактора.
- **Elgato Stream Deck (Аппаратный контроллер):** Физический пульт оператора для вызова детерминированных действий без переключения контекста:
  - Вызов команды сохранения из буфера (`save`).
  - Быстрый осмотр состояния (`git status`, `git diff`).
  - Управление жизненным циклом вахты (`vahta.py status`, `vahta.py close`).
  - Пакетная распаковка полезной нагрузки (`apply_payload.py`).

### Запреты:
1. Запрещено использовать ручную вставку многострочного кода (`Cmd+V`) и терминальные конструкции Heredoc (`cat << 'EOF'`).
2. Запрещено размещать репозиторий ядра внутри синхронизируемых папок облачных дисков.
3. Запрещено выполнять запись на диск напрямую из браузерного скрипта в обход локальной утилиты `save` и санкции оператора.
