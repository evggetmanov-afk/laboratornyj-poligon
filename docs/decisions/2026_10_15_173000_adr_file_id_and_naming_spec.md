# Регламент сквозной нумерации файлов и привязки ID в YAML

## A. Проблема (Контекст)
При поступлении заметок и данных из буфера обмена или чата возникал разрыв между именем файла на SSD и его внутренним идентификатором. Использование минутной точности (`YYYY_MM_DD_HHMM`) требовало регулярного добавления суффиксов коллизий (`_01`), а отсутствие жесткой привязки `id` в YAML-шапке к физическому имени файла усложняло индексацию и сквозную аналитику в Obsidian (Dataview).

## B. Физика среды и инварианты
1. Входящие сущности получают уникальный номер строго в момент первого физического поступления в систему.
2. Формат штампа времени: секундный слитный `YYYY_MM_DD_HHmmss` (например, `2026_10_15_173000`).
3. Поле `id` в YAML frontmatter строго тождественно базовому номеру в имени файла (`id == filename_stem`).
4. Принцип неизменяемости: один раз присвоенный `id` и имя файла не модифицируются при переносах между этапами конвейера (`inbox` -> `ready` -> `docs`).
5. Защита от коллизий: при совпадении секунды используется трехзначный суффикс `_001`, `_002` как в имени файла, так и внутри поля `id`.

## C. Решение и запреты
1. **Решение:**
   - Закрепить шаблон штампа: `%Y_%m_%d_%H%M%S`.
   - При формировании чистовых карточек в чате и при сыром сбросе утилитами присваивать единый `id`.
   - Утилиты сохранения обязаны проверять наличие YAML frontmatter и гарантировать соответствие `id` имени файла.
2. **Запреты:**
   - Запрещено переименовывать файл или менять `id` после его первичной записи.
   - Запрещено создавать карточки в `docs/` и `ready/` без заполненного поля `id` в YAML-шапке.
   - Запрещено использовать разделители между часами, минутами и секундами (только слитный блок `HHmmss`).
