# Инвариант: Двухуровневая маршрутизация инцидентов (Logging First)

## 1. Онтология уровней
1. **Уровень 0: Системный (Платформа / Ядро):**
   - Сбои базовой инфраструктуры (`.scripts/`, Raycast, zsh, Git, права APFS).
   - Сбои системного сборщика вахты (`vahta.py`), линтера (`validate_scripts.py`).
   - Сетевые отказы (`exit code 128`, Remote Guard, GitHub sync).
   - Любые сбои, возникшие при работе в корне репозитория (`/Лабораторный_полигон`).
   - **Физический адрес:** `Вахтенный_журнал/YYYY-MM-DD.md` (корень).

2. **Уровень 1: Проектный (Предметная область):**
   - Сбои прикладных скриптов проекта (FFMPEG, Whisper, анализ видео, расчет биомеханики).
   - Логические и прикладные отказы модулей проекта (например, `tennis_blitz`).
   - Любые отказы терминала при работе внутри подкаталога `01_projects/<имя_проекта>/`.
   - **Физический адрес:** `01_projects/<имя_проекта>/journal/YYYY-MM-DD.md`.

## 2. Алгоритм детекции пути
- Скрипт захвата анализирует текущий рабочий каталог процесса (`$PWD`):
  1. Если путь содержит фрагмент `01_projects/<project_name>`, целевым журналом назначается локальный каталог `01_projects/<project_name>/journal/YYYY-MM-DD.md`.
  2. В остальных случаях (корень репозитория, системные папки, внешние директории) запись направляется в корневой `Вахтенный_журнал/YYYY-MM-DD.md`.
- Создание каталогов назначения обязательно выполняется с флагом `mkdir(parents=True, exist_ok=True)`.

## 3. Negative Constraints
- Запрещено смешивать прикладные ошибки проектов с системным журналом ядра.
- Запрещено прерывание скрипта с ошибкой `FileNotFoundError` при отсутствии папки журнала.
- Запрещено перекрестное попадание логов одного проекта в контекст другого.
