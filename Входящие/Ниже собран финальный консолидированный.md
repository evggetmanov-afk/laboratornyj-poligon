# Ниже собран финальный консолидированный

Ниже собран финальный консолидированный документ, готовый для сохранения в файл базы знаний (например, Knowledge_Pipeline_Spec.md). В нём зафиксированы все утверждённые решения, структура файлов и пошаговая дорожная карта.

СПЕЦИФИКАЦИЯ И ДОРОЖНАЯ КАРТА ПРОЕКТА

Проект: «Файловый конвейер атомизации знаний (Knowledge Flow Pipeline)»
Версия: 1.0 (MVP)
Статус: Согласовано к реализации
Базовый принцип: File-as-a-State-Machine (Файловый канбан на локальной шине)

1. Замысел и базовые ограничения

⚬ Цель: Автономное преобразование сырых мыслей и заметок в стандартизированные атомарные карточки знаний через цепочку изолированных ролевых агентов: Архитектор → Исполнитель → Ревьюер.
⚬ Исключение человека из конвейера: Человек подает сырой текст на вход и забирает верифицированный результат на выходе.
⚬ Формат карточки: Сквозная полная история. Итоговый файл в папке завершенных задач сохраняет все 4 секции разбора (исходный вход, ТЗ архитектора, артефакт исполнителя, аудит ревьюера) для 100% трассируемости.
⚬ Среда выполнения: Локальная рабочая станция (скрипт-симулятор в терминале, работающий с локальной директорией или смонтированной папкой облачного диска).

2. Топология каталогов

Knowledge_Pipeline/
├── 01_INBOX/           # Вход: сюда человек кладет сырую мысль (task_xxx.md)
├── 02_TO_EXECUTE/      # Очередь Исполнителя (файл дополнен ТЗ Архитектора)
├── 03_TO_REVIEW/       # Очередь Ревьюера (файл дополнен решением Исполнителя)
├── 04_DONE/            # Архив: полностью верифицированные карточки (APPROVED)
├── 05_ESCALATE/        # Исключения: ошибки, тупики, превышение лимита доработок
└── logs/               # Системный журнал работы скрипта

4. Логика переходов и конечный автомат

1. Фаза Архитектора (01_INBOX → 02_TO_EXECUTE):
  ⚬ Читает Секцию 1.
  ⚬ Формирует неделимый тезис, границы и 3 бинарных критерия приемки (DoD).
  ⚬ Заполняет Секцию 2, ставит status: ARCHITECTED, перемещает файл в 02_TO_EXECUTE.
2. Фаза Исполнителя (02_TO_EXECUTE → 03_TO_REVIEW):
  ⚬ Читает Секции 1, 2 (и замечания из Секции 4, если это повторный прогон).
  ⚬ Собирает целевую карточку знаний strictly по критериям DoD.
  ⚬ Заполняет Секцию 3, ставит status: EXECUTED, перемещает файл в 03_TO_REVIEW.
3. Фаза Ревьюера (03_TO_REVIEW → 04_DONE или 02_TO_EXECUTE / 05_ESCALATE):
  ⚬ Сверяет Секцию 3 с критериями из Секции 2 (оценка строго бинарная, без вкусовщины).
  ⚬ Если APPROVED: заполняет Секцию 4, ставит status: APPROVED, перемещает файл в 04_DONE.
  ⚬ Если REJECTED и retries < max_retries: инкрементирует retries: 1, вписывает замечания в Секцию 4, перемещает файл назад в 02_TO_EXECUTE.
  ⚬ Если REJECTED и retries >= max_retries: ставит status: ESCALATED, перемещает файл в 05_ESCALATE для ручного вмешательства.

5. Дорожная карта реализации (От простого к сложному)

Этап 1: Ручной пошаговый режим (Step-by-step)

⚬ Цель: Изолированная отладка каждого агента и проверка парсинга Markdown.
⚬ Механика: Скрипт вызывается вручную для выполнения ровно одного действия над конкретным файлом (например: выполнить только такт Архитектора и остановиться).
⚬ Критерий готовности: Файл корректно обогащается секциями без поломки разметки и перемещается в следующую папку.

Этап 2: Пакетный сквозной прогон по требованию (Batch Run)

⚬ Цель: Проверка сквозной связки от начала до конца за один вызов.
⚬ Механика: Пользователь помещает файл в 01_INBOX и запускает скрипт одной командой без аргументов. Скрипт последовательно проводит файл через все этапы до 04_DONE (или 05_ESCALATE) и завершает работу.
⚬ Критерий готовности: Успешная отработка сквозного цикла, включая корректное ветвление при сценарии возврата на доработку (retries = 1).

Этап 3: Циклический фоновый демон (Polling Watcher)

⚬ Цель: Полная имитация автономной работы конвейера.
⚬ Механика: Скрипт запускается в фоне или отдельном окне терминала, циклически проверяет папки с интервалом в 15–30 секунд и автоматически подхватывает новые файлы.
⚬ Критерий готовности: Пользователь сохраняет заметку в 01_INBOX, не прикасается к терминалу и через пару минут видит готовый результат в 04_DONE.
