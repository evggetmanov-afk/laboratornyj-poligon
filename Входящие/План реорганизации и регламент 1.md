# План реорганизации и регламент

### План реорганизации и регламент работы «Полигона»

---

#### 1. Структура папок на диске

В корне проекта создаются только понятные функциональные зоны:

```text
/полигон/
│
├── ПРАВИЛА.txt               ← Единственный документ со всеми правилами
├── _quarantine/             ← Временный карантин для сомнительных файлов
│
├── 00_ОБЩЕЕ/                 ← Только проверенные общие скрипты и утилиты
│
└── 01_ПРОЕКТЫ/               ← Изолированные папки экспериментов
    ├── 2026-10_задача_А/
    │   ├── вход/             ← Данные только для этого опыта
    │   ├── выход/            ← Результат обработки
    │   ├── скрипт.py         ← Рабочий код задачи
    │   └── ЗАМЕТКА.txt       ← Дневник опыта (что пробовали и сработало ли)
    │
    └── 2026-10_задача_Б/
        └── ...

```

---

#### 2. Пошаговый порядок наведения порядка

1. **Создать резервную копию:** полностью скопировать папку проекта на другой носитель или в отдельный архив. До подтверждения копии ничего не менять.
2. **Создать файл `ПРАВИЛА.txt` в корне:** зафиксировать там структуру папок и правила работы.
3. **Создать папку `_quarantine/`:** переместить туда все дубликаты, непонятные файлы и папки со странными именами.
4. **Проверить работоспособность:** запустить текущие рабочие задачи. Если что-то не запустилось — вернуть из карантина только недостающий файл.
5. **Разложить оставшееся:**
* Общие стабильные инструменты перенести в `00_ОБЩЕЕ/`.
* Текущие рабочие задачи разложить по отдельным папкам в `01_ПРОЕКТЫ/`.


6. **Очистить карантин:** удалить `_quarantine/` только после того, как система стабильно отработает 1–2 недели без сбоев.

---

#### 3. Содержание файла `ПРАВИЛА.txt` (для подачи в LLM)

Текст, который помещается в файл `ПРАВИЛА.txt` и отдается модели перед началом сессий:

> **ПРАВИЛА РАБОТЫ В ПРОЕКТЕ «ПОЛИГОН»**
> 1. **Изоляция задач:** Любая новая задача или эксперимент создается строго в отдельной папке внутри `01_ПРОЕКТЫ/`. Запрещено вносить изменения в файлы других проектов.
> 2. **Защита ядра:** Папку `00_ОБЩЕЕ/` запрещено менять без прямого указания пользователя.
> 3. **Запрет мусора:** Запрещено создавать новые папки вне своего проекта, а также плодить файлы с суффиксами `_v2`, `_copy`, `_final`. Правки вносятся строго в существующие файлы.
> 4. **Дневник эксперимента:** В конце работы над задачей создать или обновить в папке проекта файл `ЗАМЕТКА.txt` по форме:
> * Какая задача решалась?
> * Какой прием или логика сработали?
> * Что не сработало и почему отброшено?
> * Что из этого опыта можно вынести в `00_ОБЩЕЕ/`?
> 
> 
> 5. **Стиль общения:** Без псевдонаучных терминов и канцелярита. Только понятные формулировки и прямые действия.
> 
>
