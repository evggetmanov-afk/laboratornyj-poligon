# Этот недостающий узел в

Этот недостающий узел в архитектуре называется **Реестром (Индексом-манифестом)** или **Картой местности (Map of Content / Keyfile)**.

Без него система мгновенно воспроизведет ту же проблему: карточки есть, но чтобы их найти, придется вспоминать, где они лежат, открывать браузер, листать NotebookLM и тратить ресурс внимания.

Встраиваем этот **Ключ** прямо в физическую файловую систему проекта.

---

### Обновленная схема со встроенным Ключом (INDEX)

```
                   [ ЭТАП 1: ТЕКУЩИЙ ЧАТ ]
                 «Цех первичной обработки»
                             │
                             ▼  Экспорт
               [ МАРШРУТНЫЙ ФАЙЛ: ABC_VAULT.md ]
                             │
     ┌───────────────────────┴───────────────────────┐
     ▼                                               ▼
[ РЕПОЗИТОРИЙ ]                                [ NotebookLM ]
.swap/docs/abc_vault.md                        Внешний архив
     │                                               ▲
     │                                               │
     ▼                                               │ (прямая ссылка)
┌───────────────────────────────────────────────┐    │
│  ★ КЛЮЧ К БАЗЕ: .swap/INDEX.md                │    │
│  - Прямой URL блокнота в NotebookLM ──────────┼────┘
│  - Карта карточек (A1, A2, B1, B2, C1...)     │
│  - Быстрые якоря и термины тезауруса          │
│  - Команды вызова для терминала / Raycast     │
└───────────────────────┬───────────────────────┘
                        │
                        ├──────────────────────────┐
                        ▼                          ▼
               [ ЧЕЛОВЕК / ТЕРМИНАЛ ]       [ ИСПОЛНИТЕЛЬ / АГЕНТ ]
             Открывает один файл INDEX     Читает только назначенный
             и сразу видит всю карту       якорь или путь к C-кванту

```

---

### Как устроен этот Ключ (`.swap/INDEX.md`)

Файл ключа кладется прямо в корень каталога `.swap/` и содержит четыре жестких блока:

```markdown
# КЛЮЧ К СИСТЕМЕ (SYSTEM INDEX & REGISTRY)

## 1. ВНЕШНИЕ СВЯЗИ
- NotebookLM Vault: [Прямая ссылка на конкретный блокнот]
- Git-репозиторий: laboratornyj-poligon (branch: main)

## 2. КАРТА КАРТОЧЕК (Локальный путь: .swap/docs/abc_vault.md)
| ID | Уровень | Название сущности | Назначение |
| :--- | :--- | :--- | :--- |
| A1 | Смысл | Проблема «человека-кабеля» | Почему нельзя копировать вручную |
| A2 | Смысл | Конфликт дерева целей и LLM | Границы восприятия машины |
| B1 | Механика | Протокол файла подкачки | Контракт взаимодействия сессий |
| B2 | Механика | Жизненный цикл кванта | 4 фазы от задумки до коммита |
| C1 | Контракт | Спека .swap/TASK.md | Точные поля и формат кванта |
| C2 | Контракт | Манифест .swap/A_FRAME.md | Неизменяемые правила и табу |

## 3. ТЕЗАУРУС (БЫСТРЫЕ ЯКОРЯ)
- [Квант работы](#квант-работы) — неделимый шаг с тестом.
- [Инвариант](#инвариант) — правило, запрещенное к нарушению.
- [Файл подкачки](#файл-подкачки) — диск как буфер между чатами.

## 4. ШАБЛОН ДИРЕКТИВЫ ДЛЯ НОВОГО ЧАТА
«Читай .swap/INDEX.md, работаем по карточке [ID], обнови .swap/TASK.md»

```

### Почему это снимает проблему судорожного поиска:

1. **Единая точка входа:** Вам больше не нужно помнить структуру каталогов или искать ссылку в закладках браузера. Достаточно открыть `.swap/INDEX.md` в редакторе или вывести его в терминале.
2. **Прямой мост в NotebookLM:** Если нужно глубоко порефлексировать или задать вопрос по архиву, кликается ссылка из раздела 1 — вы сразу в нужном блокноте.
3. **Адресация для модели:** Новому чату не надо скармливать всю базу. Вы говорите: *«Используй карточку B2 из INDEX.md»*, и модель точечно берет только то, что требуется.

Теперь система замкнута: мысль превращается в карточки, карточки получают адреса, а адреса сведены в один файл-ключ. Переходим к генерации самого содержимого (`ABC_VAULT.md` и `INDEX.md`)?
