# RULES.md

1. НАЗНАЧЕНИЕ
Спокойно проверять новые идеи с текстом и кодом, не ломая проверенные инструменты и сохраняя контроль над файлами.

2. СТРУКТУРА ПАПОК
/00_core_tools/   — стабильные скрипты ядра, системные промпты и методология ABC. Менять файлы здесь без прямой команды запрещено.
/00_system_cards/ — инварианты, правила надежности, матрицы отказов и протоколы защиты среды.
/01_projects/     — изолированные папки под каждое направление (например, /01_projects/tennis_blitz/). Внутри задачи свои папки: in, out, локальный код, локальный промпт под проект и смысловые карточки.
/_draft/          — временная песочница с нулевой ценностью. Данные отсюда удаляются в любой момент без предупреждения.
/_quarantine/     — временное хранилище сомнительных файлов перед удалением и разбором.

3. ПРАВИЛА ДЛЯ МОДЕЛИ (И ДЛЯ НАС)
- Детерминированный ход: если следующий шаг очевиден из логики процесса, формулируй его сразу как прямое предложение к действию без встречных вопросов. Задавай вопросы только при наличии двух равнозначных архитектурных альтернатив.
- Такт работы и квитирование: модель выполняет ровно один такт за раз, завершает его конкретным предложением следующего шага и ожидает подтверждения (+++, == или текстовой команды) перед переходом к реализации.
- Структура рассуждений: сначала системный инвариант и логика среды, затем предметная специфика проекта, без смешивания уровней абстракции в одном предложении.
- Изоляция контуров: системные правила и карты надежности хранятся в /00_system_cards/. Предметный код и заметки проекта изолированы внутри своего каталога в /01_projects/. При работе в диалоге разделяй эти уровни по смыслу.
- Защита ядра: при работе внутри проектов запрещено менять файлы в /00_core_tools/.
- Простой язык: писать глаголами действия без псевдонаучных терминов, канцелярита и корпоративного жаргона.
- Именование каталогов: все системные папки, пути проектов, скриптов и шлюзов именуются строго латиницей в нижнем регистре без пробелов (snake_case). Кириллица допустима исключительно внутри названий самих заметок.
- Конкурирующие гипотезы: при параллельном сравнении двух решений создаем файл с говорящим именем сути (например, test_knn.py рядом с test_tree.py).
- Создание новых папок: создавать новые каталоги в корне или внутри /01_projects/ разрешено только по прямому запросу и с подтверждения пользователя.

4. ТЕХНИКА БЕЗОПАСНОСТИ ПРИ ЧИСТКЕ
- Фиксация состояния: перед чисткой фиксируем рабочий срез локально (контрольная точка или коммит Git).
- Сначала карантин: сомнительные и временные файлы переносим в /_quarantine/.
- Проверка запуском: запускаем рабочий сценарий. Если упал — возвращаем из карантина только недостающий элемент.
- Окончательная очистка: /_quarantine/ разбирается и очищается только после подтверждения стабильности.
