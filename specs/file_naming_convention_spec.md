# Спецификация: Стандарт именования файлов и идентификации сущностей конвейера

## 1. НАЗНАЧЕНИЕ И ОБЛАСТЬ ДЕЙСТВИЯ
Спецификация определяет правила формирования имен файлов, сквозных идентификаторов и классификационных меток для документов, проходящих через конвейер обработки (`00_raw_inbox/` -> `01_inbox/` -> `ready/` -> `archive/`), а также для карточек базы знаний.

Цель стандарта — обеспечить детерминированную идентификацию данных, исключить коллизии и отделить рабочий статус документа от его смыслового содержания.

---

## 2. СИСТЕМНЫЕ ИНВАРИАНТЫ

### 2.1. Тождественность ID и временного штампа
- Базовым уникальным идентификатором сущности является секундный штамп времени монолитного формата `YYYYMMDDHHmmss` (строго 14 цифр подряд без подчеркиваний и дефисов).
- Значение штампа в имени файла строго тождественно полю `id` в YAML-заголовке (frontmatter) документа.
- Любое несовпадение имени файла и поля `id` расценивается парсерами как критическая ошибка целостности данных.

### 2.2. Неизменяемость при перемещении (Immutability)
- Имя файла и его `id` присваиваются в момент первичной нормализации (на этапе входа в конвейер через шлюз) и остаются неизменными на всех стадиях жизненного цикла:
  `00_raw_inbox/` -> `01_inbox/` -> `ready/` -> `archive/`
- Переход документа между этапами конвейера выражается исключительно сменой каталога расположения и обновлением поля `stage` в YAML-заголовке. Переименование файла при смене статуса категорически запрещено.

### 2.3. Разделение юрисдикций: Каталог vs Метаданные
- **Каталог (папка):** Управляет только процессом и состоянием готовности (где документ находится в конвейере обработки).
- **Имя файла и метаданные:** Фиксируют неизменяемую сущность, ее происхождение, классификацию и смысловое содержание.

### 2.4. Разрешение коллизий времени
- Если два документа поступают в течение одной секунды, уникальность обеспечивается добавлением числового суффикса коллизии:
  `YYYYMMDDHHmmss_001`, `YYYYMMDDHHmmss_002`.
- Суффикс коллизии становится неотъемлемой частью базового идентификатора и синхронно отражается в поле `id` YAML-заголовка.

## 3. СТРУКТУРА ИМЕНИ ФАЙЛА

Имя нормализованного файла строится по строгому шаблону:

`<timestamp_id>[_<collision_index>][tags] <semantic_title>.md`

Примеры:
- `20261015210541 [core][task][poly] deploy_runner.md`
- `20261015210541_001 [core][task][poly] deploy_runner.md`
- `20261015210541 test_note.md`
