# Инженерная спецификация: Шлюз входящих и сквозной след технологии (inbox_gateway_spec)

## 1. НАЗНАЧЕНИЕ ВЕРСТАКА
Лабораторный полигон — верстак для создания технологий. Входящий сигнал (сбой, мысль, сырая таблица, медиа) проходит через тиски полигона до тех пор, пока не превратится в воспроизводимый инструмент, скрипт или регламент.
Главная цель архитектуры шлюза — обеспечить непрерывную прослеживаемость (Traceability): любой единичный факт может породить целое дерево расследования и разработки, доступное для мгновенной сборки через Obsidian Dataview.

## 2. ЗАКОН ВЕСА: ПАСПОРТ И ТЕЛО
1. **Легкие текстовые сущности:** Текст заметок, правила, спецификации и скрипты ядра хранятся непосредственно в репозитории на SSD макбука под контролем Git (Контур 1).
2. **Тяжелые и внешние объекты (видео, аудио, дампы, PDF-сканы, тяжелые таблицы):**
   - **Физическое тело:** Размещается вне Git — либо локально на SSD макбука (в изолированном каталоге вне репозитория), либо на Google Диске (Контур 2).
   - **Карточка-паспорт:** Текстовый `.md`-файл в репозитории, содержащий монолитный `id`, описание и путь `ref_path` к физическому телу.

## 3. СТАНДАРТ МОНОЛИТНОГО КЛЮЧА (Zettelkasten Compact)
Идентификатор является синтетическим машинным ключом, а не текстом для человеческого чтения.
- Формат: 14-значный монолит `YYYYMMDDHHmmss` без разделителей, дефисов и пробелов.
- Обеспечивает мгновенное выделение двойным кликом и гарантирует естественную хронологическую сортировку.
- Дата для чтения оператором выносится в отдельное поле `created` (ISO).

## 4. СВЯЗКА КЕЙСА: ЛИЧНЫЙ ID И РОДОВОЙ ID (case_id)
1. **Личный ID (`id`):** Уникальный пожизненный номер конкретного листа/события.
2. **Родовой ID (`case_id`):** Номер корня дерева, из которого выросла технология.
   - У первичной карточки в сыром буфере `case_id` равен собственному `id`.
   - У всех производных карточек (задачи, баги, решения, артефакты) личные `id` уникальны, а `case_id` наследуется без изменений.
3. **Независимость имен файлов:** Физическое имя файла на диске может быть любым (с любым суффиксом или без него). Поиск, связывание и построение витрины Dataview опираются исключительно на поля метаданных `id` и `case_id`.

## 5. ОНТОЛОГИЯ ТРАНСФОРМАЦИИ
При движении по конвейеру материал меняет онтологическую категорию:
- **Факт (`type: fact`):** Событие физической реальности, лог, прецедент.
- **Закон (`type: invariant`):** Неустранимое свойство или ограничение среды.
- **Правило (`type: rule` | `type: decision`):** Регламент или архитектурное решение (ADR).
- **Задача (`type: task`):** Вектор действия с глаголом исполнения.
- **Артефакт (`type: artifact`):** Готовый код, утилита или инструмент.
