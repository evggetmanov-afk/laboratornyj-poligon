# ADR-001: Единый источник правды (PROJECT_PASSPORT.md вместо RULES.md)

## 1. Проблема (A)
Размазывание правил по нескольким файлам (`RULES.md`, `PROJECT_PASSPORT.md`, инструкции в промптах) приводило к коллизиям: правила противоречили друг другу, модель путалась в приоритетах, а оператор тратил время на поиск актуального регламента.

## 2. Физика среды и барьер (B)
Внимание LLM (attention window) деградирует при наличии дублирующихся или конфликтующих инструкций в контексте. При чтении двух файлов с правилами модель выбирает случайный или последний по токенам вариант, нарушая инварианты системы.

## 3. Решение (C)
- Файл `RULES.md` полностью упразднен.
- `PROJECT_PASSPORT.md` объявлен единственной Конституцией и неделимым источником правды.
- Вся архивная история вынесена из Паспорта в базу знаний (`docs/`).

## 4. Ограничения (Negative Constraints)
- Запрещено создавать вспомогательные файлы общих системных правил вне `PROJECT_PASSPORT.md`.
- Запрещено вносить в Паспорт исторические логи и даты изменений.

# ADR-002: Протокол физической реальности и запрет симуляции записи

## 1. Проблема (A)
Модель рапортовала оператору словами «Файл успешно сохранен», «Команда выполнена», «Записано на диск», хотя физически команда еще даже не копировалась в терминал. Оператор терял связь с реальным состоянием файловой системы на SSD.

## 2. Физика среды и барьер (B)
LLM не имеет прямого доступа к исполнению команд в терминале macOS без внешнего агента. Генерация текста моделью — это математическое предсказание токенов, а не системный вызов ядра ОС. Словесное обещание модели не создает байтов на диске.

## 3. Решение (C)
- Внедрен жесткий пункт №10 Паспорта: модель готовит текст для применения, но не подтверждает успех до получения фактического вывода от оператора.
- Введен протокол верификации: отчет модели строится только на основе поступившего текстового лога терминала (`git status`, `git diff`, `ls`).

## 4. Ограничения (Negative Constraints)
- Категорически запрещено использовать глаголы совершенного вида прошедшего времени («сохранено», «записано», «создано») по отношению к операциям на диске без лога терминала.
- Запрещено генерировать интерактивные команды с подтверждением в консоли (`read`, `rm -i`).

# ADR-003: Двухуровневая модель записи на диск (Heredoc vs Payload)

## 1. Проблема (A)
Попытки редактировать большие файлы скриптов и заметок через мелкие патчи, поиск строк или интерактивный ввод приводили к поломке синтаксиса, потере кавычек, битым кодировкам и разрыву Heredoc из-за невидимых символов.

## 2. Физика среды и барьер (B)
Буфер обмена терминала macOS искажает длинные команды со спецсимволами (`$`, `\`, кавычки), если они не экранированы. При развертывании нескольких файлов за раз ручной ввод команд перегружает оператора и провоцирует ошибки вставки.

## 3. Решение (C)
Разделение потоков записи на два уровня (пункт №9 Паспорта):
- **Уровень 1 (Ядро):** Изменение системных файлов выполняется строго через монолитный Heredoc (`cat << 'EOF'`) с жестким pre-flight check стандарта `terminal_heredoc_standard.md`.
- **Уровень 2 (Проекты и Документация):** Пакетная выгрузка десятков файлов выполняется через парсер `scripts/apply_payload.py` по спецификации `payload_generator_spec.md`.

## 4. Ограничения (Negative Constraints)
- Запрещено генерировать команды записи ядра без наличия текста `specs/terminal_heredoc_standard.md` в контексте сессии.
- Запрещено генерировать частичные диффы для ручной правки скриптов; запись ведется только целыми файлами.
