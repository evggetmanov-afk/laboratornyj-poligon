# Регламент обработки ошибок и инцидентов

Документ фиксирует рабочий контур оперативной фиксации сбоев в лабораторном полигоне.

## 1. Архитектура контура
- **Терминал / Среда выполнения**: Источник ошибки. При возникновении сбоя текст выделяется и копируется в буфер обмена (`Ctrl+C` / `Cmd+C`).
- **Скрипт захвата (`.scripts/capture_error.py`, иконка 🔬)**: Активный инструмент оперативного контура. Считывает текст из буфера обмена (с поддержкой `pbpaste` и резервным методом через `osascript`), дополняет таймстемпом и записывает в хронологический файл текущего дня. Успешное выполнение подтверждается звуковым сигналом (`Glass.aiff`).
- **Служебные утилиты (`.scripts/close_shift_++++.py`, `.scripts/drive_audit.py`, иконка ⚙️)**: Вспомогательные фоновые сценарии (закрытие вахты, аудит хранилища) без привязки к оперативным горячим клавишам первого уровня.
- **Хранилище («Вахтенный_журнал/YYYY-MM-DD.md»)**: Единая точка сбора всех ежедневных инцидентов и логов.

## 2. Стандартный сценарий работы при инциденте
1. Происходит сбой в терминале.
2. Пользователь выделяет проблемный фрагмент текста и копирует его в буфер обмена.
3. Запускается скрипт захвата (`capture_error.py`).
4. Инцидент автоматически падает в сегодняшний файл вахтенного журнала в виде готового блока со временем и текстом ошибки.
