# Инженерная спецификация: Браузерный шлюз и контракт TASK_PAYLOAD

## 1. НАЗНАЧЕНИЕ
Регламентация протокола бесконтактной передачи артефактов, кода и задач из веб-интерфейса чата модели (Контур Архитектора) в локальную файловую систему полигона (Контур Исполнителя) через буфер обмена macOS без ручной правки путей и без прямого запуска непроверенных команд.

---

## 2. АРХИТЕКТУРА И РОЛИ КОНТУРОВ
- **Окно 1 (Браузер / Архитектор):** Веб-чат LLM с длинным контекстом. Формирует стратегию, генерирует детерминированный блок `TASK_PAYLOAD` и снабжает его кнопкой быстрого копирования через UserScript (Tampermonkey).
- **Шлюз передачи (macOS Clipboard):** Промежуточный изолятор. Предотвращает несанкционированное выполнение скриптов в операционной системе.
- **Окно 2 (Терминал / Исполнитель):** Локальная среда полигона на MacBook. Читает полезную нагрузку через `pbpaste | python3 scripts/apply_payload.py` либо пофайлово через алиас `save`.

---

## 3. СТРУКТУРА И СИНТАКСИС КОНВЕРТА TASK_PAYLOAD

Конверт полезной нагрузки выдается моделью в едином блоке кода с маркером формата:

```json
{
  "protocol_version": "1.0",
  "task_id": "YYYYMMDD_HHMMSS",
  "project": "Лабораторный_полигон",
  "manifest": [
    {
      "path": "относительный/путь/к/файлу.ext",
      "action": "create | overwrite | patch",
      "encoding": "utf-8",
      "content": "Содержимое файла целиком"
    }
  ],
  "pre_flight_cmd": "немодифицирующая команда проверки перед записью",
  "verification_cmd": "команда валидации после применения (Definition of Done)"
}
