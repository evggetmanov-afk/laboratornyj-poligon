# Архитектура полигона

## 1. Философия и назначение
«Лабораторный полигон» представляет собой строго управляемую, отказоустойчивую инженерно-архитектурную среду и универсальный надпрограммный комплекс. Система создана для безопасной автоматизации, накопления структурированного опыта и отработки алгоритмов взаимодействия человека с ИИ-ассистентами. Архитектура построена на принципе разделения человеческого смысла (контекст, философия, преемственность) и жесткого машинного контракта.

## 2. Концепция «Источника правды» (Source of Truth)
Вся система базируется на четком разделении сред:
* **Оперативная среда (Чат):** Временная зона обработки информации, генерации гипотез и обсуждений. Чат подвержен деградации контекста (Context Rot) и **не является** хранилищем данных.
* **Истинный источник правды (Git-репозиторий и Obsidian):** Локальная файловая структура на жестком диске и удаленный репозиторий GitHub (`origin/main`). Ни одно решение, знание или артефакт не считаются существующими, пока они не зафиксированы в файле, не прошли локальный коммит и барьер синхронизации.

## 3. Физическая структура и анатомия программы (Дерево каталогов)
Репозиторий организован в виде строго структурированного пространства знаний и автоматизации:
* **`README.md`** — корневой навигатор и реестр уставных документов проекта.
* **`Инструкция пользователя.md`** — пошаговые алгоритмы оперативного управления полигоном, структура пакета вахты и команды оператора.
* **`Архитектура полигона.md`** — системный манифест, описывающий концепцию, структуру и операционные циклы.
* **`ERROR_WORKFLOW.md`** — регламент фиксации и обработки сбоев (Logging First).
* **`Стандарт_Безопасного_Транспорта_И_CLI.md`** — жесткие инженерные ограничения для работы в оболочке `zsh`.
* **`Хроника_Полигона.md`** — дашборд аудита (Dataview) для мониторинга вахтенных журналов и карточек.
* **`Вахтенный_журнал/`** — хроника смысловых смен (разовые файлы `Журнал YYYY-MM-DD.md`) и инцидентов (`Инциденты YYYY-MM-DD.md`).
* **`Входящие/`** — буфер оперативной фиксации сырых мыслей (накопительный дневник или разовые заметки).
* **`Система/`** — внутренний служебный контур:
  * **`Промпты/`** — системные контракты взаимодействия (`Системный_Промпт.md`, `Протокол_Заступления_На_Вахту.md`).
  * **`Регламенты/`** — стандарты скриптов и интерфейсов.
* **`.scripts/`** — исполнительная автоматизация (`vahta.py`, `vahta.sh`, `capture_error.py`).
* **`Карточки/`** — база структурированных знаний со статусами (`сырое` → `обработано` → `проверено`).

## 4. Операционный цикл, пакет вахты и потоки данных
Жизненный цикл информации в системе обеспечивает непрерывность без деградации контекста:
1. **Оперативный фиксатор (Входящие):** Сырые мысли и идеи фиксируются как *дополнение дневника* или *разовая заметка*.
2. **База знаний (Карточки):** Проектные материалы оформляются в виде атомарных карточек со статусом `сырое` для контроля через дашборд `Хроника_Полигона.md`.
3. **Такт «Думаем» / «Делаем»:** Обсуждения переносятся в файлы по команде оператора с соблюдением стандартов CLI (`cat << 'EOF'`). При переходе к такту «Делаем» фиксируется промежуточное состояние локальной рабочей директории с проверкой объективных параметров (`git status`).
4. **Фиксация и Смена вахты (Пакет вахты):** Отправка в удаленный репозиторий (`git push origin main`) выполняется исключительно при сдаче вахты. Скрипт `.scripts/vahta.py` формирует пакет вахты (системный промпт, протокол заступления и свежий вахтенный журнал), копируя его в буфер обмена (`pbcopy`) со звуковым сигналом `Pop.aiff` для запуска нового чистого чата.

## 5. Контур безопасности и инженерные стандарты CLI
Для предотвращения сбоев оболочки (`zsh`) и деформаций данных действуют ограничения:
* **Запрет опасных конструкций:** Запрещены цепочки команд через `&&`, `||`, `;`, а также выполнение кода аргументами в `python3 -c`.
* **Безопасный транспорт:** Любая запись в файлы выполняется исключительно через каноническую конструкцию `cat << 'EOF' > путь`.
* **Remote Guard:** Ни одна задача не считается завершенной без проверки внешнего паритета (`git status` строго `Your branch is up to date with 'origin/main'`).

## 6. Протокол обработки ошибок (Logging First)
При возникновении сбоев в терминале действует правило нулевой толерантности:
* Любая ошибка немедленно фиксируется в суточном журнале инцидентов (`Вахтенный_журнал/Инциденты YYYY-MM-DD.md`) до попыток исправления кода.
* Для мгновенного сброса аномалий используется автономный перехватчик `.scripts/capture_error.py`.
