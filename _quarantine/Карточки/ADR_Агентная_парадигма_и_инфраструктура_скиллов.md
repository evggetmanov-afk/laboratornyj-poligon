# ADR: Агентная парадигма, архитектура скиллов и интеграция через API

> **Ключевой вопрос:** Каким образом перейти от линейных скриптов-копировщиков к масштабируемой агентной экосистеме без потери контроля оператора?

### 1. Контекст и предпосылки
Классическая линейная автоматизация («скрипт скопировал файл из точки А в точку Б») исчерпала себя. Для обработки разнородных потоков (теннисная тактика, статистика матчей, системная инженерия) требуется семантическая маршрутизация и глубокая аналитическая предобработка. При этом сохраняется фундаментальное требование: предотвратить риск потери ключевых деталей и не допустить превращения системы в неуправляемый «черный ящик».

### 2. Принятое решение
1. **Переход к агентной архитектуре:** Взаимодействие выстраивается через агентов и специализированные модули навыков (skills).
2. **Контракт навыка (Skill Contract):** Каждый скилл представляет собой детерминированный модуль с фиксированной ролью, набором доступных инструментов (Tools / API) и строгим контрактом входных/выходных данных.
3. **Оправданность API:** Использование программных API (Google Drive API, LLM Function Calling) утверждается как базовый стандарт взаимодействия, обеспечивающий работу без привязки к графическому интерфейсу.
4. **Режим полуавтоматического контроля (Human-in-the-loop):** Базовым режимом работы агентов-маршрутизаторов является подготовка артефактов со статусом pending_review. Финальная верификация остается за человеком-экспертом.
5. **Демаркация сред:** Проектирование и калибровка промптов/регламентов агентов ведутся на «Лабораторном полигоне». Исполняемые пайплайны и среда вызова API размещаются в «AI_Pipeline».

### 3. Последствия и ограничения
* **Плюсы:** Высокая гибкость, возможность динамического подключения новых алгоритмов без переписывания общей структуры, автоматическое извлечение ключевых вопросов.
* **Ограничения:** Требуется строгая изоляция токенов доступа и секретов, а также протоколирование каждого шага работы агента (Logging First).
