# Как это устроено Модель

Как это устроено: Модель карточек задач
Вместо статического имени файл сразу создается с временным индексом:
tasks/2026_10_15_1345_save_clip_sound.md (или в .swap/tasks/).

Формат метки: YYYY_MM_DD_HHMM_[краткий_слаг].md.

tasks/
├── 2026_10_15_0910_raycast_hotkey.md     (статус: DONE)
├── 2026_10_15_1320_fix_task_lifecycle.md (статус: IN_PROGRESS)
└── 2026_10_15_1800_streamdeck_macro.md   (статус: DRAFT)
Почему это снимает всю головную боль
Можно начинать сколь угодно рано (Инкубация):
Пришла идея во время прогулки или за чаем — создал файл 2026_10_15_1410_идея_автосохранения.md, набросал пару строк, поставил статус DRAFT. Файл спокойно лежит, никто его не затрет и скрипт его не сожжет.

Никаких пустых перезаписей:
Больше нет операции «очистить TASK.md до дефолтного шаблона». Файл создается один раз при появлении мысли, дополняется в процессе и там же остается.

Хронологический порядок из коробки:
Команда ls tasks/ в терминале или дерево в Obsidian сразу выстраивают задачи в идеальную цепочку по времени. Не нужно гадать, в какой вахте что происходило.

Симлинк на текущую задачу (active):
Чтобы скрипты save_clip.py или vahta.py всегда знали, с чем сейчас идет работа, достаточно держать мягкую ссылку или указатель:
.swap/CURRENT_TASK -> tasks/2026_10_15_1320_fix_task_lifecycle.md.

Как выглядит жизненный цикл теперь
Старт мысли:
Создается карточка с текущим временем (можно горячей клавишей или командой вроде task new "название"). Статус: DRAFT.

Работа:
Пока задача формулируется и кодится — файл редактируется. Никакой спешки закрывать смену. Статус: IN_PROGRESS.

Финал:
Тесты прошли, переводим статус в DONE.
vahta close теперь просто коммитит этот файл в Git и добавляет строку в журнал дня. Сам файл никуда не исчезает и не затирается.
