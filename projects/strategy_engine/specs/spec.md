# Спецификация блока: Двухконтурный генератор и исполнитель стратегий

## 1. Архитектурная модель
Блок реализует разделение зон ответственности по принципу «Вероятностный синтез -> Детерминированное исполнение»:

1. **Контур А (Генератор стратегии / Архитектор):**
   - Среда: LLM (Stateful / Gemini Web).
   - Задача: Прием задачи оператора, сбор ограничений, декомпозиция на атомарные шаги по формуле A1 -> A2 -> B -> C.
   - Результат: Детерминированная карточка стратегии (Task Sheet) с жесткими Negative Constraints.

2. **Контур Б (Кодер / Исполнитель шага):**
   - Среда: LLM (Stateless Desktop / Чистый лист).
   - Задача: Получение ровно одного шага из карточки, выдача чистого кода или диффа без диалогового шума.

3. **Контур С (Механический раннер / Контролер):**
   - Среда: macOS / Python CLI / bash. Без участия LLM.
   - Задача: Последовательный запуск шагов стратегии, проверка физических предусловий (pre-flight checks), фиксация кодов возврата и логов.

## 2. Структура карточки стратегии (Task Sheet)
Каждая стратегия формируется в формате:
- `ID`: STRAT-YYYYMMDD-XX
- `ЦЕЛЬ`: Конечный физический результат.
- `ИНВАРИАНТЫ`: Запреты и правила среды, которые нельзя нарушать.
- `ШАГИ (Ordered Steps)`:
  - Шаг N: Действие, входные файлы, ожидаемый код возврата, критерий валидации.
- `ROLLBACK`: Инструкция отката при сбое на шаге N.

## 3. Протокол исполнения (Runner Engine)
1. Раннер читает карточку стратегии.
2. Проверяет наличие всех зависимостей перед стартом каждого шага.
3. Выполняет шаг. При коде возврата != 0 останавливает конвейер и возвращает статус FAIL с указанием точки останова.
4. При успешном завершении всех шагов ставит статус DONE.
