# REQ-002: Двухконтурный цикл управления

## 1. Суть требования
Работа с большими языковыми моделями разделяется на два функционально изолированных контура для предотвращения деградации контекста:
1. **Первый контур (Стратегический / Архитектор):** сессия с непрерывным контекстом, где формируются правила, проектируются онтологии и готовятся детерминированные ТЗ.
2. **Второй контур (Исполнительный / Эфемерный):** однотактные изолированные сессии с нулевой историей, которые принимают ТЗ, возвращают ровно один артефакт и закрываются.

## 2. Ограничения (Negative Constraints)
- Исполнителю второго контура запрещено принимать архитектурные решения или выбирать формат выдачи.
- Сессии второго контура не накапливают историю диалога.

## 3. Критерии приемки (DoD)
1. Регламент двухконтурной работы зафиксирован в документации ядра.
2. Любая задача передается исполнителю только при отсутствии архитектурных развилок в ТЗ.
