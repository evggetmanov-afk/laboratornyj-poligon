# REQ-004: Неизменяемость путей и ссылочная целостность

## 1. Суть требования
Исходные карточки требований в `01_Inbox/Baseline_Requirements/` сохраняют свои имена и пути на протяжении всего жизненного цикла системы. Изменение состояния карточки (в работе, закрыто, отложено) производится только мутацией поля `status` в YAML-блоке.

## 2. Ограничения (Negative Constraints)
- Категорически запрещено перемещать файлы между папками для имитации стадий Канбан-доски.
- Запрещено переименовывать ID карточек после их первичной фиксации в Git.

## 3. Критерии приемки (DoD)
1. Внутренние ссылки вида `[[REQ-001]]` остаются рабочими вне зависимости от этапа реализации.
2. Проверка истории изменений файла в Git сохраняет непрерывную историю без переименований путей.
