# REQ-007: Фиксация архитектурных решений через ADR

## 1. Суть требования
Любое изменение технологического стека, структуры каталогов, правил связывания или соглашений по именованию оформляется в виде Архитектурного решения (Architecture Decision Record, ADR) в каталоге 00_System/Decisions/.

## 2. Ограничения (Negative Constraints)
- Запрещено внедрять структурные изменения на основе устных договоренностей в чате без создания файла ADR-xxx.
- Принятые ADR не удаляются; в случае отмены решения создается новый ADR со статусом superseded.

## 3. Критерии приемки (DoD)
1. Создан шаблон 00_System/Templates/tpl_adr.md.
2. Первые прецеденты (ADR-001 по изоляции и ADR-002 по инкубации) зафиксированы в каталоге решений.
