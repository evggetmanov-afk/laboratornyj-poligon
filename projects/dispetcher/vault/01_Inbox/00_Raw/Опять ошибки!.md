Метод уплощения строки (_Inline Payload Injection_) ломается в **четырех конкретных физических сценариях**:

### 1. Пересечение кавычек (Quote Collision)

Команда оборачивается во внешние кавычки шелла — например, `python3 -c "..."`.

Внутри текста используются одинарные (`'`), а в Markdown часто встречаются:

- Апострофы в английском тексте (`don't`, `it's`).
    
- Одинарные кавычки в цитатах.
    
- Внутренние двойные кавычки (`"..."`).
    

Если внутри текста попадется та же кавычка, что и снаружи строки, шелл воспринимает её как закрытие аргумента. Следующее слово становится неизвестной командой, и терминал выбивает:

Plaintext

```
zsh: parse error near ...
zsh: command not found
```

### 2. Подстановка переменных и спецсимволов шелла (Expansion Trap)

Если внешняя строка заключена в двойные кавычки (`"..."`), шелл пытается выполнить подстановку **до того**, как строка дойдет до Python:

- **Знак доллара (`$`)**: `$VAR` или формулы LaTeX (`$f(x) = ...$`) шелл расценит как переменные окружения и сотрет их (заменит на пустую строку) либо сломается.
    
- **Обратные апострофы (`` `command` ``)**: шелл попытается запустить команду внутри бэктиков в фоновом режиме (_command substitution_).
    
- **Символы `!`**: в интерактивном Zsh/Bash запускают поиск по истории команд (`history expansion`).
    

### 3. Лимит на длину аргументов операционной системы (`ARG_MAX`)

В macOS (и Linux) существует физический предел размера параметров командной строки:

- Переменная `ncargs` в ядре macOS (обычно около 256–1024 КБ).
    
- Если передавать этим методом большую заметку, файл с логами или объемный исходник, система выдаст системный отказ на уровне ядра:
    

Plaintext

```
zsh: argument list too long
```

### 4. Некорректное двойное экранирование (Double Escape Corruption)

Если в исходном тексте уже содержались обратные слэши (пути Windows `C:\path`, регулярные выражения `\d+`, экранированные переносы `\\n` или LaTeX `\frac{a}{b}`):

- Шелл съедает один уровень слэшей при парсинге аргумента.
    
- Python съедает второй уровень слэшей при чтении литерала.
    
- В результате на диск пишется искаженный текст без нужных слэшей или вылетает `SyntaxError: (unicode error) 'unicodeescape' codec can't decode bytes`.
    

**Итог:** Этот метод годится только для коротких служебных вызовов (1–3 строки без сложной разметки).

Для полноценных заметок Markdown, где всегда есть бэктики кода ` ``` `, кавычки, списки и формулы, он ненадежен. Именно поэтому единственный 100% стабильный шлюз — это **подача тела через поток `stdin` (`sys.stdin.read()`) в постоянный скрипт-станок**, где шелл вообще не касается содержимого файла.
