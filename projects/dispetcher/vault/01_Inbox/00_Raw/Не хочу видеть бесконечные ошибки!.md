Я подозревал, что такой метод есть, но до этого LLM пытался мне говорить: "Создай Python-файл, вставь туда содержание и теперь запусти".

Разница между этими подходами фундаментальная — это водораздел между **ручным трудом оператора** и **детерминированным инструментальным станком**.

В инженерных пайплайнах и автоматизации это классифицируется так:

### 1. Как это называется

- **Интерактивный ручной метод (Manual Copy-Paste / Human-as-a-Clipboard):**
    
    Подход, когда модель говорит: _«Создай файл, скопируй, вставь, сохрани, запусти»_. Модель перекладывает механическую работу на человека.
    
- **Автогенерация / Самосборка (Self-contained Bootstrap / Hands-off Provisioning):**
    
    Подход, когда вы получаете **одну монолитную CLI-команду**, которая:
    
    1. Сама создаёт `.py` файл на диске.
        
    2. Сама запускает его через системный интерпретатор.
        
    3. Сама удаляет временный файл после успешного исполнения.
        

### 2. Почему первый вариант («создай файл сам») неэффективен

Когда модель просит человека вручную создать файл и вставить код:

1. **Когнитивное трение:** вам нужно переключиться в редактор (VS Code, Nano, TextEdit), создать файл с точным именем, не ошибиться с директорией, вставить код, сохранить его и снова переключиться в терминал.
    
2. **Риск невидимых символов:** текстовые редакторы macOS (особенно если это не IDE, а стандартные заметки или TextEdit) любят подменять прямые кавычки `"` на типографские «лапки» `“”` или менять отступы табов на пробелы. Для Python нарушение отступов (IndentationError) фатально.
    
3. **Разрушение квантования:** такт растягивается на 5–6 мелких механических действий вместо одного факта запуска.
    

### 3. Инженерный принцип: «Станок делает, оператор санкционирует»

В нормальной архитектуре (где ваш репозиторий «Лабораторный полигон» — это станок, а база знаний — изделие):

- Оператор не должен работать буфером обмена между окнами.
    
- Модель обязана упаковать задачу в **единый автономный квант**.
    
- Оператор только принимает архитектурное решение («делаем»), вставляет команду и видит проверяемый результат в Git.
    

Именно поэтому связка:

Bash

```
cat << 'PYEOF' > scripts/temp.py
...
PYEOF
python3 scripts/temp.py
rm scripts/temp.py
```

является каноническим паттерном одноразового генератора (**Disposable Scaffolding Script**): ноль ручной рутины, строгая изоляция от парсера шелла и гарантированная чистота после завершения.

# SPEC-CLI-001: Регламент детерминированной генерации артефактов через эфемерный скрипт

## 1. Суть правила (Core Principle)
Любое программное создание или пакетная модификация файлов на диске силами LLM оформляется как **единый самодостаточный квант исполнения** (Self-contained Disposable Script). 

Модель формирует монолитную команду для терминала, которая самостоятельно записывает временный скрипт-генератор на диск, выполняет его системным интерпретатором и удаляет временный файл после отработки.

---

## 2. Канонический паттерн реализации (Gold Standard)

```bash
cat << 'PYEOF' > scripts/_temp_generator.py
import os

target = "/absolute/or/relative/path/to/target_file.md"
content = """Содержимое целевого файла без риска коллизий кавычек и шелла"""

with open(target, "w", encoding="utf-8") as f:
    f.write(content.strip() + "\n")

print("OK: Target file created.")
PYEOF
python3 scripts/_temp_generator.py
rm scripts/_temp_generator.py
````

## 3. Физические обоснования (Physics of Environment)

1. **Изоляция от парсера оболочки (Shell Escape Immunity):**
    
    Маркер `cat << 'PYEOF'` (с одинарными кавычками вокруг ограничителя) указывает оболочке (Zsh/Bash) передавать тело документа «как есть», отключая раскрытие переменных (`$VAR`), подстановку команд и реакцию на обратные апострофы (`` ` ``).
    
2. **Обход буферных коллизий (Bracketed Paste Trap):**
    
    Сложные тексты (Markdown с кодовыми блоками, таблицы Dataview, многострочные кавычки), вставляемые напрямую через `python3 -c '...'` или неэкранированный шелл, неизбежно переводят терминал в режим зависания ввода (`quote>`, `heredoc>`). Файловый дескриптор Python читает данные напрямую из файловой системы в кодировке UTF-8, минуя буфер терминала.
    
3. **Устранение когнитивного трения оператора (Zero Clipboard Overhead):**
    
    Оператор выполняет роль контролирующего шлюза (Human-in-the-Loop), а не ручного переносчика текста между окнами редактора.
    

## 4. Системные запреты (Negative Constraints)

1. **Запрет ручной вставки (Anti-Manual Protocol):**
    
    Категорически запрещено инструктировать оператора паттернами вида: _«Создай файл X, открой редактор, вставь туда код ниже, сохрани и затем запусти команду Y»_.
    
2. **Запрет inline-вызовов с сложным телом:**
    
    Запрещено передавать многострочные тексты, содержащие обратные апострофы или кавычки, через аргументы однострочников `python3 -c '...'`.
    
3. **Запрет оставления мусора (Zero-Residue Invariant):**
    
    Любой вспомогательный скрипт генерации обязан содержать команду безусловной зачистки за собой (`rm scripts/_temp_generator.py`). В репозитории не должны оставаться одноразовые генераторы.
    
4. **Запрет неконтролируемого молчания:**
    
    Скрипт обязан печатать явный результат выполнения (`OK: ...`), чтобы оператор мгновенно фиксировал успешность такта без ручного вызова `ls` или `cat`.
