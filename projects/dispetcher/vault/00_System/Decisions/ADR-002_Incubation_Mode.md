# ADR-002: Инкубационный режим хранилища внутри проектов Полигона

## 1. Контекст и проблематика
На начальном этапе (Фаза 0: Инкубация) создание сразу двух физически разнесенных независимых репозиториев создает операционное трение при переключении контекстов и маршрутизации скриптов. Требуется этап созревания ядра без риска поломки истории Git.

## 2. Рассмотренные альтернативы
- Альтернатива 1: Немедленное создание внешнего репозитория на одном уровне с Полигоном. Отвергнута на Фазе 0 для снижения трения развертывания.
- Альтернатива 2: Использование Git submodule внутри Полигона. Отвергнута из-за сложности синхронизации указателей коммитов и риска ошибок оператора.
- Альтернатива 3: Размещение хранилища в изолированной поддиректории projects/dispetcher/vault без вложенного .git, с временным версионированием через репозиторий Полигона. Принята.

## 3. Принятое решение
1. Хранилище «Диспетчер» размещается по пути projects/dispetcher/vault/.
2. Вложенный репозиторий .git на этапе инкубации НЕ создается.
3. Все коммиты, затрагивающие хранилище, маркируются строгим префиксом vault(tact-xxx): ...
4. Приложение Obsidian открывается строго на каталоге vault/, сохраняя локальную целостность ссылок.
5. По завершении разбора базовых требований хранилище вычленяется в самостоятельный репозиторий.

## 4. Последствия
- Положительные: мгновенный старт, работа из привычного терминала, непрерывная страховка истории через Git Полигона.
- Ограничения: строгое соблюдение префиксов коммитов для чистого последующего экспорта.
