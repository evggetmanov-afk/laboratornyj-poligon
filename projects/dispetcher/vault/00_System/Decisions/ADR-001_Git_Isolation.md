# ADR-001: Физическая изоляция инструментального станка и хранилища знаний

## 1. Контекст и проблематика
При разработке сложных систем с участием LLM и локальных автоматизаций возникает смешение инструментального окружения (скрипты, виртуальные среды, временные файлы) и базы знаний (архитектура, онтология, карточки решений). Накопление служебного мусора в базе смыслов приводит к деградации структуры, разрастанию репозитория и порче ссылочной целостности.

## 2. Рассмотренные альтернативы
- Альтернатива 1: Монолитный репозиторий, где скрипты и хранилище Obsidian живут вперемешку. Отвергнута из-за риска загрязнения базы знаний и неконтролируемого дрейфа схем.
- Альтернатива 2: Хранение заметок внутри облачных папок (Google Drive) с прямым запуском Git. Отвергнута из-за риска повреждения базы версий Git фоновыми демонами синхронизации.
- Альтернатива 3: Физическое разделение на два независимых контура: станок (Полигон) и изделие (Хранилище Obsidian). Принята.

## 3. Принятое решение
Принят принцип разделения сред (Аксиома II Манифеста):
1. Лабораторный полигон является внешним инструментальным станком.
2. Obsidian-хранилище является чистым изделием.
3. Ни один служебный байт среды выполнения (кэши .pyc, venv, логи) не проникает в чистовую базу смыслов.

## 4. Последствия
- Положительные: гарантированная чистота базы знаний, независимое управление версиями, предсказуемый аудит через git diff.
- Отрицательные: необходимость явной настройки путей взаимодействия между станком и хранилищем.
