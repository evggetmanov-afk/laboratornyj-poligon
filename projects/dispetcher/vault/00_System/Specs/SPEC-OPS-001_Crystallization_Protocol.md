# SPEC-OPS-001: Протокол кристаллизации сущностей

## 1. Назначение
Детерминированный шлюз переноса сущностей из контура входящих (01_Inbox/) в контур концептов (02_Notes/). Исключает повреждение файловой структуры, рассинхронизацию реестра и сбои синтаксиса шелла при передаче многострочного Markdown.

## 2. Физический контракт станка
Единственной точкой входа для создания концептов является:
projects/dispetcher/scripts/crystallize.py

### Сигнатура вызова:
python3 projects/dispetcher/scripts/crystallize.py <REQ_ID> <CN_ID> <CN_SLUG> <TITLE> <TAGS> < /tmp/_payload.md

### Параметры:
1. REQ_ID — идентификатор входящего требования (например, REQ-002).
2. CN_ID — целевой идентификатор концепта (например, CN-002).
3. CN_SLUG — системное имя файла без пробелов (например, Two_Tier_Architecture).
4. TITLE — читаемое наименование концепции.
5. TAGS — теги через запятую без пробелов.
6. stdin — чистое тело заметки, передаваемое через поток ввода из изолированного буферного файла.

## 3. Negative Constraints (Инженерные запреты)
- Запрещено создавать или модифицировать файлы в 02_Notes/ напрямую через терминальные однострочники python3 -c или ручной bash-скриптинг.
- Запрещено передавать многострочный Markdown с кавычками и спецсимволами в аргументы командной строки шелла.
- Запрещено закрывать такт кристаллизации в обход автоматического коммита и реестра 00_System/INBOX_REGISTRY.md.
