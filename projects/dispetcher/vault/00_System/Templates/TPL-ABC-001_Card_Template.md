# Стандарт и шаблон монолитной карточки ABC

## 1. Назначение
Спецификация архитектуры хранения, правил жизненного цикла и эталонного формата монолитной карточки сущности. Служит целевым контейнером для результатов работы метода `abc_transformation_method`.

---

## 2. Архитектурные правила карточки

1. **Монолитность (1 сущность = 1 файл):** Все три грани сущности (A, B, C) обязательно хранятся внутри одного файла. Разносить грани по отдельным документам запрещено.
2. **Направление калибровки:** Изменения и уточнения идут строго однонаправленно: A -> B -> C.
3. **Закон идентичности (Правило ветвления):**
   * Уточнение 1 или 2 граней — это **калибровка** (фиксируется новой ревизией внутри текущей карточки).
   * Одновременное коренное изменение всех трёх граней (A + B + C) признаётся **деривацией (новой сущностью)**. Старая карточка замораживается как исторический факт, рядом создаётся новая карточка с новым ID.
4. **Приоритет локального тезауруса:** Терминология опирается исключительно на локальный словарь репозитория проекта. Внешние академические понятия привлекаются только по прямой команде оператора.
