Архитектурное решение (ADR): Многочатовый конвейер и гибридный полигон детерминированного исполнения

Статус: Утверждено (Approved)
Дата: 24 октября 2026 г.
Контекст системы: Проект «Лабораторный полигон» (macOS, Python 3, Git, Obsidian, Stream Deck, mpv IPC)

1. Контекст и проблематика (Context & Problem Statement)

При непрерывном диалоге с большими языковыми моделями (LLM) неизбежно накапливается энтропия:

1. Контекстная деградация и дрейф (Context Drift): При объединении в одном окне рассуждений, архитектурного проектирования, написания кода и разбора ошибок модель начинает галлюцинировать, возвращает ранее исправленные баги, «забывает» системные ограничения и выдает ленивый псевдокод вида # ... остальное без изменений ....
2. Стохастичность вместо детерминизма: Попытка поручить LLM непосредственные операции с файловой системой, генерацию последовательных ID, контроль валидности схем и управление состоянием приводит к нерегулярным сбоям (ошибки YAML, поломка двусторонних ссылок, перезапись файлов).
3. Высокая когнитивная нагрузка на оператора: Ручная рутина (переключение между десятками вкладок, копирование трейсбеков, формулирование длинных промптов при каждой ошибке) утомляет оператора и разрушает темп работы.

Ключевой вызов: Обеспечить строгую воспроизводимость и детерминизм системы, сохранив когнитивную мощь LLM в анализе и синтезе, но полностью исключив вероятностные ошибки при выполнении операций в реальной среде.

2. Принятое решение (Decision)

Развернуть трехконтурный конвейер с физическим аппаратным управлением, в котором зоны ответственности строго разграничены по принципу «Вероятностное мышление \rightarrow Детерминированное исполнение \rightarrow Физический контроль»:

                       ┌───────────────────────────────┐
                       │          STREAM DECK          │
                       │ [Task] [Run] [Green] [Review] │
                       └───────┬──────────────┬────────┘
                               │              │
           ┌───────────────────┘              └──────────────────┐
           ▼                                                     ▼
    [КОНТУР А (Web)]                                      [КОНТУР С (macOS)]
    Браузер / Gemini Web                                  Python CLI / stdlib / APFS
    • Роль: Архитектор / Арбитр                           • Роль: Механический библиотекарь
    • Память: Stateful (Такт N)                           • Валидация YAML, генерация ID
    • Формула: A1 -> A2 -> B -> C                         • Pre-flight тесты (ассерты среды)
           │                                                     │
           ▼ (Task Card)                                         ▼ (Готовый артефакт)
    [КОНТУР Б (Desktop App)] ──────────────────────────────► [Файловая система / Vault]
    Нативный клиент / Чистый лист                         Obsidian / Git / scripts/
    • Роль: Инженер-кодер
    • Память: Stateless (Cmd+N)
    • Вывод: Чистый код / diff


3. Архитектура контуров и матрица ответственности

Контур А: «Архитектор / Дистиллятор / Арбитр»

⚬ Среда исполнения: Браузер (Gemini Web).
⚬ Модель памяти: Stateful (хранит состояние). Ведет непрерывную историю, фиксирует хронологию тактов [Такт N], поддерживает точки отката (/откат N).
⚬ Функции:
  ⚬ Прием неструктурированных мыслей, логов и голоса оператора.
  ⚬ Четырехслойная дистилляция по протоколу:
    ⚬ A1 (Голос): Дословная фиксация авторского ядра без подмены терминов.
    ⚬ A2 (Телеология): Вскрытие истинной цели и архитектурного намерения.
    ⚬ B (Физика среды): Учет ограничений ОС, сокетов, процессов и файловой системы.
    ⚬ C (Преобразователь): Выпуск квантованной спецификации (Task Card) с блоком Negative Constraints.
  ⚬ Роль «Арбитр инвариантов» (/арбитр): При аварии на полигоне разбирает инцидент по формуле:
    
    $$\text{Факт} \longrightarrow \text{Причина (брешь в ТЗ)} \longrightarrow \text{Дельта} \longrightarrow \text{Новый Negative Constraint}$$

Контур Б: «Инженер / Кодер»

⚬ Среда исполнения: Нативное приложение macOS (Desktop Client).
⚬ Модель памяти: Stateless (без сохранения истории). Сессия сбрасывается (Cmd + N) после каждого спринта или квантованной задачи.
⚬ Функции:
  ⚬ Получение самодостаточного Task Card из Контура А.
  ⚬ Категорический отказ от учета глобальных тактов проекта (ликвидация иллюзии непрерывности).
  ⚬ Генерация чистого, полностью компилируемого кода, диффа или JSON без преамбул, вежливых фраз и сокращений.

Контур С: «Механический библиотекарь и контролер»

⚬ Среда исполнения: Локальная ОС macOS (Python 3.10+, bash, zsh). Строго без участия LLM.
⚬ Функции:
  ⚬ Ingest-шлюз: Забор markdown-блока из системного буфера обмена (pbpaste), очистка от текста LLM, валидация YAML-схем.
  ⚬ Генератор физических ID: Сканирование каталогов Obsidian, вычисление индекса +1, предотвращение коллизий и затирания файлов (TASK-YYYYMMDD-XX.md).
  ⚬ Pre-Flight Runner: Локальный запуск скриптов с жесткими физическими проверками (exit code, размер выходных файлов > 0 байт, валидность JSON, активность IPC-сокетов /tmp/mpv.socket).
  ⚬ Фиксатор вахты: Генерация выходных карточек HANDOFF-*.md и создание git-коммитов.

Аппаратный слой: «Stream Deck»

⚬ Назначение: Аппаратный контроллер конечного автомата (State Machine) конвейера:
  1. [Key 1: NEW TASK] — Вызов vault_ingest.py: забирает буфер, регистрирует задачу в Obsidian, подготавливает очищенный промпт для Контура Б.
  2. [Key 2: RUN TEST] — Вызов раннера полигона: запуск в песочнице, проверка ассертов.
  3. [Key 3: GREEN / HANDOFF] — Создание Handoff Card, фиксация git commit, подготовка строкового отчета для Контура А.
  4. [Key 4: REVIEW / FAIL] — Сбор stderr и упавшего трейсбека, упаковка в команду /арбитр и копирование в pbcopy для немедленной передачи в Контур А.

5. Последствия и системные эффекты (Consequences)

Положительные (Advantages)

⚬ Изоляция сбоев: Ошибка кодогенерации локализуется в Контуре Б и не разрушает стратегический контекст Контура А.
⚬ Абсолютный детерминизм данных: Файлы, даты и связи в Obsidian управляются программным кодом Контура С, а не вероятностными галлюцинациями нейросети.
⚬ Устранение синдрома «неполного кода»: Изоляция Контура Б (Stateless) вынуждает модель генерировать целостные скрипты, исключая огрызки # ... без изменений ....
⚬ Тактильная эргономика: Управление циклом через 4 кнопки Stream Deck сводит рутинные операции к механическим нажатиям без поиска окон и вкладок.
⚬ Самообучающаяся база инвариантов: Каждая ошибка фиксируется в виде карточки Fail Card, непрерывно обогащая постоянные запреты (Negative Constraints) системы.

Отрицательные и риски (Risks & Mitigations)

⚬ Риск «Грязного буфера» (Clipboard Race): Случайный захват постороннего текста из буфера.
  ⚬ Компенсатор: Скрипт Контура С парсит только строго ограниченные блоки --- ... ---, игнорирует внешний шум и выдает системный аудиосигнал об ошибке схемы.
⚬ Риск «Ложного зеленого света» (False Green-Light): Скрипт отработал с кодом 0, но проглотил ошибку через pass.
  ⚬ Компенсатор: Тестовый раннер Контура С проверяет физические ассерты (непустой файл, валидный JSON, отклик процесса), а не только код возврата.
⚬ Дисциплинарная нагрузка на первом этапе: Необходимость строго соблюдать протокол вручную до написания скриптов.
  ⚬ Компенсатор: Поэтапное внедрение: сначала ручной прогон 10–15 карточек \rightarrow затем автоматизация Контура С \rightarrow затем финальная привязка к Stream Deck.

6. План внедрения (Rollout Phases)

1. Фаза 1 (Стабилизация протокола): Проведение первых 10–15 сквозных циклов вручную через буфер обмена macOS. Накопление первичного каталога карточек сбоев (Fail Cards) и кристаллизация Negative Constraints.
2. Фаза 2 (Программный Контур С): Развертывание локального скрипта tools/vault_ingest.py (парсинг pbpaste, валидация YAML, безопасная запись в vault Obsidian).
3. Фаза 3 (Аппаратная интеграция): Настройка рабочего профиля Stream Deck на 4 клавиши, подключение вызовов osascript для автоматического переключения фокуса между окнами macOS.
4. Фаза 4 (Синхронизация RAG-зеркала): Настройка односторонней синхронизации статического глоссария терминов из Obsidian в Google Drive для мгновенного контекстного доступа из Gemini Web.
