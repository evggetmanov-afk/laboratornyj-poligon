# Двухконтурная архитектура: Архитектор / Исполнитель

## Проблема длинного контекста
При ведении длинных непрерывных сессий с LLM в одном окне нарастает контекстная энтропия:
1. Модель накапливает шум промежуточных итераций и начинает терять системные ограничения.
2. Отладка кода и анализ сырых данных забивают окно контекста мусором.
3. Время отклика (Time to First Token) деградирует по мере роста длины диалога.

## Принцип разделения контуров
Система разделяется на два независимых слоя:

```
[ Верхний контур: Стратег / Архитектор ]
       │ (Длинный контекст, ведение проекта, выработка решений)
       ▼
[ Шлюз: TASK_PAYLOAD ]
       │
       ▼
[ Нижний контур: Изолированный Исполнитель ]
         (Свежий контекст, узкая задача, автовалидация, возврат в буфер)
```

### Верхний контур (Архитектор)
- **Среда:** Основное рабочее окно диалога (браузер / AI Studio).
- **Зона ответственности:** Общая картина системы, декомпозиция задач, регламенты, аудит расхождений.
- **Ограничение:** Не выполняет генерацию чернового кода и рутинный парсинг сырых логов.
- **Выходной артефакт:** Стандартизированный блок `### TASK_PAYLOAD`.

### Нижний контур (Исполнитель / Песочница)
- **Среда:** Изолированная сессия (фоновая вкладка браузера на этапе 1, локальный API-воркер на этапе 2).
- **Зона ответственности:** Автономная генерация решения, прогон через внутренние тест-кейсы, фильтрация служебного шума.
- **Ограничение:** Не хранит историю предыдущих тактов, прекращает существование сразу после выдачи результата.
- **Выходной артефакт:** Очищенный результат, помещенный напрямую в системный буфер обмена.
