# ADR 002: Архитектура атомарных шпаргалок оператора и динамической сборки через Dataview

## 1. Контекст и проблематика
С ростом количества инструментов ядра (`vahta.py`, `apply_payload.py`, Heredoc, Git, контуры хранения) удержание команд и форматов в памяти оператора создает когнитивную перегрузку и риски ошибок. 
Существующие монолитные документы (`PROJECT_PASSPORT.md`, спецификации `specs/`) избыточны для быстрого контекстного вызова в рабочей сессии.
Требуется система подсказок, удовлетворяющая требованиям:
1. Атомарность: одна карточка — один узкий рабочий сценарий или инструмент.
2. Машиночитаемость: строгий YAML-frontmatter для интеграции с Obsidian.
3. Нулевые затраты на ручную каталогизацию: динамическая агрегация реестров через Dataview.

## 2. Принятое решение
Создать в ядре репозитория подсистему оперативных шпаргалок со следующей структурой и контрактами:

### 2.1. Каталог размещения
Выделить в топологии каталогов ядра директорию `manuals/` с разделением по типам или плоским списком с метаданными.

### 2.2. Стандарт метаданных (YAML-контракт карточки)
Каждая карточка шпаргалки обязана содержать frontmatter:
```yaml
---
id: YYYYMMDDHHMM_manual_<slug>
type: manual
category: <files | vahta | git | recovery | tools>
role: operator
tags: [manual, <дополнительные_теги>]
title: "<Понятный заголовок действия>"
summary: "<Краткая суть: что делает шпаргалка в одно предложение>"
updated: YYYY-MM-DD
---
2.3. Структура содержимого памятки
Назначение: когда и в каких случаях применять.

Инвариант / Ограничение: что запрещено или требует внимания.

Готовый шаблон / Команда: минимальный блок кода, готовый к копированию.

Команда проверки: как убедиться, что операция прошла успешно.

2.4. Сводный дашборд оператора (manuals/index.md)
Единый реестр собирается динамическими запросами Dataview на основе метаданных (WHERE type = "manual" с группировкой по category).

3. Системные инварианты
Карточка шпаргалки не заменяет инженерную спецификацию (specs/), а является ее эргономичной операционной выжимкой.

Создание новой памятки требует обязательного заполнения полей category и summary для попадания в дашборд.

Карточки пишутся глаголами действия на простом русском языке без вводных рассуждений.

4. Этапы реализации
Запись настоящего ADR в methodology/adr_002_operator_manuals_dataview.md.

Фиксация каталога manuals/ в разделе 3 PROJECT_PASSPORT.md.

Развертывание дашборда manuals/index.md и первой базовой серии карточек (manual_files_payload.md, manual_files_heredoc.md, manual_vahta.md).
