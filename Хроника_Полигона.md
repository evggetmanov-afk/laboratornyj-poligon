# Хроника и мониторинг полигона

Панель визуального аудита состояния заметок, статусов обработки моделями и истории изменений.

---

## 1. Записи Вахтенного журнала
```dataview
TABLE дата AS "Дата", статус AS "Статус"
FROM "Вахтенный_журнал"
SORT file.name DESC
```

---

## 2. Мониторинг обработки LLM (Зона «Карточки»)

### Требуют обработки (сырые)
```dataview
TABLE дата AS "Создано", агент AS "Крайний агент", теги AS "Теги"
FROM "Карточки"
WHERE статус = "сырое"
SORT file.name ASC
```

### Обработано агентами (на проверке)
```dataview
TABLE дата AS "Дата правки", агент AS "Исполнитель", источники AS "Источник"
FROM "Карточки"
WHERE статус = "обработано"
SORT file.mtime DESC
```

### Проверено и утверждено
```dataview
TABLE дата AS "Дата", агент AS "Автор/Агент", теги AS "Теги"
FROM "Карточки"
WHERE статус = "проверено"
SORT file.name ASC
```

## 3. Регламент аудита версий
- **Obsidian File Recovery:** Проверить в настройках (Настройки -> Восстановление файлов): интервал снимков — 5 минут, срок хранения — не менее 30 дней.
- **Git diff контроль:** Перед подтверждением изменений от LLM проверять рабочий каталог через `git status` и `git diff`.
