# Invariant: ABC Operational Loop (Operator <-> Environment <-> LLM)

## 1. Тезис (Инвариант)
> Метод ABC является закрытым инженерным контуром трансформации воли человека-оператора в детерминированные команды для LLM через аппаратный фильтр ОС. Перенос метода на спортивную педагогику или внешние объекты без изменения физики слоя B запрещён.

## 2. Физический контекст / Триггер
- **Субъект:** Человек-оператор (системная организация, постановка задачи).
- **Среда (Слой B):** Локальная файловая система APFS на MacBook, статус-коды шелла ($?), токены контекста, детерминированные утилиты (bash, git, ffmpeg).
- **Исполнитель (Слой C):** Стохастическая языковая модель (LLM), ограниченная жесткими негативными условиями.

## 3. Алгоритм действия (Цикл трансформации)
1. Слой A (Вход): Захват сырого голоса, тезиса или намерения оператора без самодеятельности модели.
2. Слой B (Фильтр среды): Проверка аппаратных фактов (существование файла, пути, вывод терминала, лимиты). Модели запрещено генерировать решение до получения отклика слоя B.
3. Слой C (Фиксация): Генерация детерминированного машинного артефакта (промпт, конфиг, файл) с обязательной проверкой записи на физический носитель.

## 4. Ограничения (Negative Constraints)
- Запрещено: признавать задачу решённой на основании словесного согласия LLM без физического подтверждения с диска.
- Запрещено: расширять границы модели ABC на биомеханику человека без предварительного проектирования новой физики среды.
- Запрещено: генерировать код или модифицировать файлы без предварительной валидации путей утилитами ОС.
